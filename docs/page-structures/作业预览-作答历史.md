# 作业预览 · 作答历史 · 做作业

从形考列表点「查看」进来。这里不答题。这里决定：要不要做作业、扫不扫码、做完后去哪对答案。

- 证据：用户给的作答历史 HTML + 做作业按钮 HTML；Chrome 现场读到 `doHomework` / `showQRCodeDialog`（不记录 token/学号）。
- 路径：`/study/assignment-preview.aspx`（中间没有 `/`）
- 查询参数：`homeWorkId`、`courseopenid`、`minorCourseOpenId`

页面上至少三块面板：

1. 网上记分作业详情（名称随作业变，样本「网上记分作业详情 - 记分作业一」）
2. 预警（可忽略）
3. 作答历史列表 `#mainContent`

## 1. 详情区（做作业从这里点）

用户 HTML 按钮区：

```html
<a class="am-btn am-btn-success am-btn-default"
   href="/study/assignment/readpreview.aspx?homeWorkId=...&courseopenid=...&minorCourseOpenId=..."
   onclick="return doHomework(this);" target="_blank">视障学生做作业</a>
<a class="am-btn am-btn-success am-btn-default"
   href="/study/assignment/preview.aspx?homeWorkId=...&courseopenid=...&minorCourseOpenId=..."
   onclick="return doHomework(this);">做作业</a>
```

| 按钮 | href | target | 自动化 |
| --- | --- | --- | --- |
| 视障学生做作业 | `/study/assignment/readpreview.aspx` | `_blank` | 不点 |
| 做作业 | `/study/assignment/preview.aspx`（中间有 `/`） | 无 target | 要做才点 |

两个按钮都是 `onclick="return doHomework(this);"`。点「做作业」不是直接跳作答页，先走 `doHomework`。

详情里还能看到（现场补充，用户未贴全量，但页面有）：

- 网上记分作业名称
- 网上记分作业类型：客观题
- 作答开始/结束时间
- 作答次数：无限制
- 已作答次数：数字
- 主观题注意事项两段（提交被批阅后不能再做等）

隐藏域名字（禁止取值入库）：`courseopenid`、`homeWorkId`、`stuId`。

## 2. 点「做作业」之后（扫码是硬暂停）

现场脚本（行业分校标记样本为 `False`，学生标记为 `True`）：

1. `throttleHref(ele, 1000)` 限流，太快点会失败。
2. 非学生 `isStudent === "False"` → 直接放行。
3. `localStorage` 里 `validateResult_` + 学号后缀已经是 `1` 或 `2` → 已验证，`handleHref` 打开作答页。
4. 行业分校 `isIndustryCollege === "True"` → 走人脸（`/faceapi/api/ulpFace/...`）。人脸失败会落到扫码。
5. **否则（普通学生、样本就是这条）→ `showQRCodeDialog(ele)`，return false，不立刻进作答页。**

扫码弹窗（脚本拼出来的，不是原生 confirm）：

| 项 | 值 |
| --- | --- |
| dialog id | `dl_qrCodeCheck` |
| 标题 | 微信扫码验证 |
| 提示 | 请使用「微信扫码进行验证」 |
| 二维码容器 | `#qrCode` |
| 状态文案 | `#qrcodeMessage`，初始「未扫码」 |
| 进入作答 | `#navigateToAnswer`，初始 `display:none` |
| 按钮 | 「取消」 |
| 取码接口 | `GET {facePrefix}/wePortalQRCode/getqr`，带 Authorization。facePrefix 生产是 `https://l.shou.org.cn/faceapi/api` |
| 轮询 | 成功取码后约 3 秒调 `checkQRCode` |

验证通过后 `handleHref` 会动态插一个 `target=_blank` 的隐藏 `<a>` 再点，作答页常在新标签打开。

用户产品要求：无头碰到扫码必须暂停，进度里标「需要扫码验证」，右边给「打开可视化浏览器进行验证」；用户扫完后在 App 点「验证完毕」再恢复无头。不要在无头里死等二维码。

已验证过的账号可能不再弹。以是否出现「微信扫码验证」弹窗为准，不要假设每次都扫。

页面内联脚本里有学号、姓名、JWT。**禁止采集、禁止写日志、禁止进题库。**

## 3. 作答历史列表（用户 HTML 权威）

容器：`#mainContent table.am-table`

| 列 | 宽 | 文案 |
| --- | --- | --- |
| 1 | 5% | 序号 |
| 2 | 25% | 提交时间 |
| 3 | 25% | 用时 |
| 4 | 15% | 批阅状态 |
| 5 | 15% | 获得分数 |
| 6 | 30% | 操作 |

用户给的四类行都要认得（现场后来可能只剩已批阅，以用户 HTML 为状态全集）：

### 3.1 未完成提交（可续做）

| 列 | 样本 |
| --- | --- |
| 序号 | 0 |
| 提交时间 | `2026-09-17 16:48:30` |
| 用时 | 空 |
| 批阅状态 | 未完成提交 |
| 获得分数 | 空 |
| 操作 | `续做` |

续做：

```text
a[onclick="return throttleHref(this);"]
href=/study/assignment/continuation.aspx
参数名：paperId, homeWorkUniqueFlag, paperStructId, homeWorkId, courseOpenId, minorcourseopenid, seconds
target=_blank
```

### 3.2 未提交记录（无操作）

| 列 | 样本 |
| --- | --- |
| 序号 | 0 |
| 批阅状态 | 未提交记录 |
| 获得分数 | `td[title]` 可能是 `0` 或 `2`，可见文本仍可为空 |
| 操作 | 空 |

### 3.3 已批阅（有分数 + 查看）

| 列 | 样本 |
| --- | --- |
| 序号 | 1 |
| 提交时间 | `2026/9/17 16:01:23` |
| 用时 | 可见 `0时:2分:14秒`，`td[title]=134`（秒） |
| 批阅状态 | 已批阅 |
| 获得分数 | 可见 `<a>100</a>`，`td[title]=100` |
| 操作 | `查看` → `/study/assignment/history.aspx`，`target=_blank` |

history 参数名：`homeWorkId`、`courseopenid`、`minorcourseopenid`、`studentWorkId`、`isStudentSubmitType`。

分数本身也可能是链接，不要把分数链当成「查看」。操作列文案必须是「查看」。

### 3.4 怎么认「刚提交的那条」

用户规则：自动提交后，最新提交记录就是这次。取作答历史里**第一条已批阅**（或提交时间最新且状态已批阅）。信息不全时不要猜分数。

有 AI 答题才需要点这条「查看」，进批改页把对的题写入题库。批改页 HTML 本轮没有，待补。

## 5. 本页最小流程

1. 读详情：作业名、类型、已作答次数。
2. 读历史：是否已有满分已批阅、是否有未完成提交。
3. 已批阅 100 分：跳过。未完成提交：不点「续做」，点「做作业」新开。
4. 点「做作业」（不要点视障）。
5. 若出现「微信扫码验证」：暂停自动化，等用户验证完毕。
6. 等到作答页 `/study/assignment/preview.aspx`。
7. 答完并提交成功后回到本页（或再打开本页），刷历史。
8. 若本次有 AI 题：对最新已批阅点「查看」，校对后写题库。

## 6. 硬坑

- `doHomework` 不是原生跳转；忽略 `onclick` 直接 `goto` href 会绕过扫码，也和用户「扫码暂停」冲突。第一期跟页面走点击。
- 绿按钮在作答页提交弹窗里是取消；本页扫码弹窗的「取消」也会中止进入作答。
- 不要用 Playwright 只读 evaluate 去读 token/学号。那些值根本不该出现在 App 日志里。
- 历史序号会重复成 0，不能当主键。用状态 + 时间 + 操作链接。
- 用户 HTML 里的续做/未提交记录，现场刷新后可能消失。三种状态都要能解析。
