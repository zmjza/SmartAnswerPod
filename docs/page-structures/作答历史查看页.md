# 作答历史查看页

## 基本信息

- 页面：已批阅作业的「查看」页
- 路径：/study/assignment/history.aspx
- 来源：真实产品 Playwright E2E 脱敏 DOM；2026-09-27 再用用户已打开的 Chrome 历史页只读核对参考答案结构。未记录账号、题干、选项正文、token、Cookie 或完整查询值
- 当前用途：提交后校对题目对错；AI 答对的题入库，题库命中但答错的题删库，页面读取失败进入待回写。参考答案优先的新分支尚属需求，不是当前实现
- 题量：按页面实际 .e-q-body 数量读取，不能写死；现场样本为 20、30、31、35、60 题

## 题目容器

每题一个 .e-q-body，题目本体位于其内部 .e-q.e-checking-q。读取顺序以 DOM 顺序为准，不使用 id 作为题号主键；现场多个题目的 id 都可能重复。

| 数据 | 读取位置 | 规则 |
| --- | --- | --- |
| 题型 | .e-q-body[data-questiontype] | 1=single、2=multiple、3=judge；其它值为 unknown |
| 题干 | .e-q-q | 取文本并规范化空白；不把分数输入框当题干 |
| 选项 | .e-q .e-a-g:is(.e-checking-a, .e-choice-a) ul > li.e-a | 判断为 e-checking-a；单选/多选为 e-choice-a。li[data-index] 是页面选项序号，单选/多选正文位于 li .ErichText > xmp；按本题选项顺序把 A/B/C 映射到正文，入库去掉展示字母前缀 |
| 用户所选 | 同上且 .checked | 可多选；只在页面显示的选项上取 |
| 题目正确 | .e-q-l .e-q-right | 存在表示该题答对 |
| 题目错误 | .e-q-l .e-q-wrong | 存在表示该题答错 |
| 单选参考答案 | .e-q .e-a-ans .e-ans-ref > span.e-ans-r | 每个 span 是一个选项字母；须对应本题选项正文，不是学生所选 |
| 多选参考答案 | .e-q .e-a-ans .e-ans-ref > span.e-ans-r | 多个 span 分别为一个字母，取完整集合，逐个对应本题选项正文 |
| 判断参考答案 | .e-q .e-a-ans .e-ans-ref > div.e-ans-r > .e-a-g p.checked | 正文为“正确”或“错误”，对应本题判断选项；这里的 checked 是参考答案节点，不同于学生选项 li.checked |
| 解析 | .e-a-analysis | 仅作页面展示，不作为答案依据 |

页面字母只用于在当前题内定位选项正文，不可把 A/B/C/D 或选项下标直接作为题库答案。选项顺序变化时，先按题型、规范化题干和排序后的选项集合命中 content_hash，再按正文回填。参考答案与学生选项 li.checked 是两套节点；不读取相邻的“解析”讲解作为答案。

### 参考答案局部结构（Chrome 现场核对，已脱敏）

~~~text
.e-q-body[data-questiontype=1 或 2]
└─ .e-q
   ├─ .e-a-g.e-choice-a ul > li.e-a[data-index] > .ErichText > xmp（各选项正文）
   └─ .e-a-ans > .e-ans-ref > span.e-ans-r（逐个字母；多选有多个）

.e-q-body[data-questiontype=3]
└─ .e-q
   ├─ .e-a-g.e-checking-a ul > li.e-a[data-index]（判断选项）
   └─ .e-a-ans > .e-ans-ref > div.e-ans-r > .e-a-g > p.checked（正确／错误）
~~~

同一题先读取参考答案，再对照该题页面展示的选项顺序／正文；li.checked 仅表示学生所选，不能用来补参考答案。无法确认对应关系时保留待处理，不猜答案；没有显示参考答案时交给原有校对／提取规则。

## 对错判定

~~~text
存在 .e-q-right  → correct=true
存在 .e-q-wrong  → correct=false
两者都不存在     → correct=null，不能校对，进入待回写
~~~

不要通过颜色、图标图片、题目分数或用户选择数量猜对错。多选题必须以页面最终 .checked 集合和题目对错标记为准。

## 当前实现与题库回写的关系（新分支尚未开发）

1. 自动提交成功后，先从预览页作答历史找到最新的「已批阅」记录及其 history.aspx 查看链接。
2. 打开该链接，解析全部 .e-q-body，按同一套 content_hash 与本次作答结果对应。
3. AI 答题且 correct=true：用页面标准答案正文写入 Supabase，source=ai_verified、verified=true，追加当前课程名。
4. AI 答题且 correct=false：不入库。
5. 题库答题且 correct=false：删除对应 content_hash，下一轮必须走 AI。
6. 页面打开失败、题目无法对应、对错标记缺失、标准答案缺失或云端读写失败：保存待回写；该份作业本轮不允许继续新开。当前 `electron/review.ts` 的选择器只能读到判断题的 `p.checked`，漏读单选／多选的 `span.e-ans-r`；但三种题型的“参考答案优先、不看学生答对与否”新分支均尚未开发，判断题也不例外。
7. 下次该账号开始检测/答题前先补待回写；补完后才决定该作业是否继续。

## 选择器边界

- 当前实现主要用于已提交结果校对；计划中的提取模式也将只读可查看的历史页参考答案。
- /study/assignment-preview.aspx 是预览/作答历史列表；/study/assignment/preview.aspx 是正在作答页；两者不能用本页选择器混用。
- 不读取隐藏域值、内联脚本、账号信息、token、Cookie 或完整 URL 查询值。
- 如果站点改版导致 .e-q-right、.e-q-wrong、.e-ans-ref 或题型属性消失，停止校对并补充本文件后再继续。
