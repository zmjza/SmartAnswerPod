# T005 无码答题模式实施计划

> 本计划在目标 1/2 文档准备阶段编制；当前目标 2/2 已完成交付。独立模块、工作台接线、内部测试、真实分层验收、旧模式回归、2.6 双平台本地包和源码推送已完成；自然慢登录/错误/空白专项、漏题/Finish 失败保持未触发或内部覆盖，当前进入待用户检查/待归档确认。

## Goal

新增一个独立 `noqr` 工作模式，从 `coursework.shou.org.cn` 唯一登录入口完成新站登录、课程/作业检测、题库只读优先与 AI 兜底作答、慢响应保存、答题卡复核、交卷、分数读取和未满分重答；同时完整继承答题模式的学生、课程、并发、无头/可视化、分页、日志、历史成绩和重答配置。除无扫码入口与不写题库外，产品行为与现有答题模式一致。

## Architecture

- 独立业务目录：目标 2/2 新增 `electron/noqr/`，承载 session、course、homework、question、answer、save、submit、score、run 和类型；实际文件名可按现有风格合并，但业务边界不得混入旧模式。
- 最小共享面：只复用账号读取、浏览器 pool、并发限制、日志、题库只读、AI 客户端和 IPC；新增共享接口不得改变旧行为。
- 调度边界：新增 `electron/workbench-coordinator.ts` 组合根，按 `work_mode` 把开始、停止、选课启动、历史入口和快照分发到旧 runner 或独立 `noqr/run`；旧 `runner.ts` 不 import 无码模块，`noqr` 也不 import 旧 runner。
- UI 边界：`src/views/HomeView.vue` 只增加“无码答题”第三项、配置显示、锁定态和状态消费；不把新站 DOM/业务逻辑放进 Vue。
- 进度边界：`electron/progress.ts` 的全局事件总线不直接承载 noqr 进度，noqr 使用独立 state/snapshot，由 workbench-coordinator 合并给工作台；避免旧 runner 消费 noqr 事件。
- 页面契约：`无码答题模式页面结构.md` 是选择器、流程、接口和异常事实来源；未取证控件不猜。
- 技术栈：Electron、Vue、TypeScript、Patchright、现有构建和测试工具，不新增框架或依赖，除非目标 2/2 有明确证据并单独说明。
