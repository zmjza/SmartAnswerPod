# 保存、提交与取分重答

上级：[[_N]]

## 作答与保存

- 单选/判断使用 `.option-item[role="radio"]` 和 `aria-checked`；多选使用 `role="checkbox"`。
- 词汇匹配使用只读 `input[name="picker"]` 与底部 Picker；复合组按子题逐位确认。
- 单题保存：`SubmitJsonAsync`；复合组保存：`SubmitAllJsonAsync`。

### L1/L2/L3

- L1：捕获本次点击产生的**新请求**，匹配当前 `workId` 和题目/题目集合。
- L2：XHR 结束、HTTP 2xx、`success:true`、`result.status:"success"`。
- L3：题号/题型/答题卡按预期推进，或最后一题显示“已是最后一题”。
- L1+L2 表示服务端已接受保存；L1+L2+L3 才允许自动化继续。
- 只有页面变化、只有 toast、只有遮罩消失、只看到题号变化均不足以证明保存。
- 请求慢时保持当前页面等待；不刷新、不重复点击；响应成功但页面未推进只观察/标记“保存成功但页面未推进”。

## 答题卡与交卷

- 答题卡只有 `.sub-question.has-answered`，或本会话内 L1+L2+L3 成功保存的“题型+题号”，可以证明已保存。
- `.is-current` 只表示当前题定位，不是保存证据；当前题只显示 `is-current` 时仍须使用本轮成功保存键。
- 首题保存前逐答题卡题位读取真实控件：每张可见卡至少一个题位，目标题号必须是明确数字并与当前题位置正向匹配，空壳卡或非数字题号直接隔离。
- 英语复合题答题卡必须使用逻辑题组真实 `group.position` 和同题型 occurrence，不能用页面全局 `cardIndex` 代替题目位置；第二张同题型卡未导航时不能复用第一组局部题号；缺少页面题号 x/y 时不能只凭局部题号或卡片顺序放行，必须 fail-closed。第一篇支持 `1 -> 2` 页面题号到达，第二篇当前态不能冒充第一篇目标行。
- 没有 `.question-card` 等答题题组容器时，仍扫描当前题面可见 textarea、文本 input、contenteditable 和文件控件并整份隔离；隐藏预渲染答题卡不参与可见结构判断。
- 答题卡入口被短暂动画遮罩覆盖时，保持页面不点选项，在答题卡总时限内等待遮罩消失后重试；永久遮罩有界失败，禁止程序化绕过命中测试。
- 主观题、文本题、富文本和文件题不进入答题卡、保存和交卷流程；发现这些控件时整份作业隔离。
- 有漏题警告时取消交卷并返回补答；不能确认漏题卷。
- 完整作答可先补 `SubmitAllJsonAsync` 再发 `FinishJsonAsync`；补保存不等于最终交卷。
- 最终交卷成功必须同时满足 `FinishJsonAsync` HTTP 2xx、`success:true`、“交卷成功!”可见和交卷按钮 `.disable-btn`。
- 交卷前必须先确认答题面已稳定：全部预期保存组 accepted、可见答题卡行数与预期组数匹配、每行有进度或本会话保存证据、无 loading/骨架/活动请求，并持续稳定窗口后才允许进入答题卡。

## 分数与重答

- 交卷后返回作业区，点击对应“作答记录(n)”，读取 `GetAnswerHistoryListJsonAsync`。
- 记录页只有标题、没有 `.record-item` 且无明确空态时，先防抖等待脚本和请求，再按刷新预算刷新；交卷后暂时空态属于等待新记录。
- 排除未完成记录，按解析后的 `finishedTime` 选最新有效记录，并与 `.record-item/.score-num` 交叉核对。
- 未满分按现有 `answer_round_limit` 和答题模式规则重答；满分跳过、次数用尽、无历史链接沿用旧语义。
- 只读分数和是否满分，不读逐题对错，不校对、不提取、不写题库。

## 作业时长统计

- 每份作业从实际进入处理开始计时，在成功保存、交卷和取分节点刷新总时长。
- 平均每题只按成功保存题位累计；复合题按题位数均摊组耗时；最长单题取各组单题均摊耗时的最大值。
- 未满分重答跨轮累计；满分跳过、规则跳过或没有成功保存题位的作业不生成假统计。
- 卡片统一显示“X分YY秒”，不显示原始毫秒。

## 停止

停止后禁止新动作；已发出的保存/交卷请求等待当前原子请求结束并记录；无法确认时标为“结果不确定”，不把晚到结果覆盖停止状态。
