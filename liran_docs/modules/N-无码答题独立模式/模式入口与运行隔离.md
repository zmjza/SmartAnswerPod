# 模式入口与运行隔离

上级：[[_N]]

## 职责

把 `noqr` 作为第三个学生级工作模式接入现有 UI 和调度，同时保持旧 `answer/extract` 业务完全独立。

## 组合根

目标 2/2 的组合根：

```text
HomeView / preload / main
          ↓
electron/workbench-coordinator.ts
       ↙               ↘
旧 electron/runner.ts   新 electron/noqr/**
```

- `workbench-coordinator` 负责开始、停止、选课启动、历史/状态入口和快照合并的模式分发。
- 旧 `runner.ts` 不 import `electron/noqr/**`，其 `answer/extract` 业务函数体不新增新站页面分支。
- `noqr/run` 不 import 旧 `runner/answer/submit/review/page-tools/detect/login` 业务实现。
- `HomeView` 只负责第三按钮、配置显示、运行锁定和状态消费，不承载新站 DOM 或业务逻辑。
- `electron/progress.ts` 的旧全局事件总线不作为 noqr 进度通道；noqr 使用独立 state/snapshot，由 coordinator 合并。

## 模式与持久化

- `WorkMode = 'answer' | 'extract' | 'noqr'`。
- `store.ts` 和 IPC/类型只增加独立 `noqr` 值；旧缺失、`null`、非法值回退 `answer`。
- 每个学生的 `work_mode`、`display_mode`、`course_scope`、`answer_round_limit` 独立保存。
- 运行中锁定，停止后恢复编辑；“应用当前配置到全部学生”同步工作模式、执行环境、课程范围和重答次数。
- 界面顺序固定为“答题 / 提取题库 / 无码答题”，无码运行时不显示旧扫码授权状态或“验证完毕”入口。

## 共享层白名单

| 类别 | 允许 | 条件 |
| --- | --- | --- |
| 纯函数 | `core/hash.ts`、`core/ai-parse.ts`、`core/concurrency.ts`、`core/course-pager.ts`、`core/live-view.ts` 的类型和纯投影 | 不改变旧行为，有回归 |
| 基础设施 | `store.ts` 账号/设置读取、`pool.ts`、`slot-pool.ts`、必要日志/进度接口 | 只调用稳定接口，不共享可变业务状态 |
| 明确禁入 | 旧 `runner.ts`、`answer.ts`、`submit.ts`、`review.ts`、`page-tools.ts`、`detect.ts`、`login.ts`、旧 `core/selectors.ts`、`bank-delete.ts`、旧 writeback/QR | 旧业务实现不得 import 无码模块 |
| 需要独立适配 | 题库读取 | 不使用 `lookupByHash`；新增 GET-only 适配 |
| 需要独立实例 | AI 请求 | 复用模型策略/解析，不共享旧 `ai.ts` 的 `asked` 和模型索引状态 |
