## 数据流

1. 设置页写入加密凭据与账号列表（本机）。
2. 取得名额后按 display_mode 启动独立的 launchPersistentContext：headless 使用 headless:true、channel:'chromium'，visual 使用 headless:false；模式在上下文生命周期内锁定。
3. 登录成功后只扫 #pane-courseList，进形考两块判定。
4. 作答：content_hash 查库；命中按 answer_texts 点正文；未命中问 AI。
5. 提交成功以作答历史新记录为准，再等已批阅校对。
6. 题库读写走 anon；失败进待回写队列（本机），不卡死其它号。
7. UI 复制粘贴导入和课程分页只增加渲染层状态与必要 IPC；不得在渲染层复制账号持久化、课程队列或答题器。

## 关键技术决策

## 2026-09-21 增量架构

### 权威状态与范围调度

- 主进程维护唯一运行快照；渲染层只展示主状态、当前动作和进度，不再生成第二套文本。
- 工作模式与课程范围使用两个正交字段：workMode=answer|extract，courseScope=all|selected。
- 可选课程结果按学生保存，仅用于本轮队列生成。执行开始后由主进程冻结配置快照和选择快照。

### 程序内二维码

- 产品浏览器检测真实站点二维码弹窗并对容器截图；主进程只以内存 PNG 和脱敏任务元数据经 IPC 下发。
- 无头和可视化分别启动真实 Playwright 上下文；二维码不触发模式切换，也不写入磁盘。
- 验证恢复必须由用户动作触发，并由主进程二次检查页面状态。

### 题库与诊断

- 查看题库继续复用 public.questions 和现有 Supabase 客户端，新增服务端分页、筛选、删除和回读确认，不创建第二张题库表。
- 密码门禁位于主进程，保存哈希、失败次数和冻结截止时间；渲染层只提交待校验文本。
- AI 连通性复用现有模型清单和请求客户端，增加最多 3 个并发的诊断调度，不改变正式答题顺序。

### 配置与本机状态

- 空闲配置保存后由主进程广播；运行时使用启动快照并拒绝热改。
- 本机状态来自真实采样，浏览器数统一从浏览器池生命周期状态聚合。

| 决策 | 选择 | 备选 | 理由 |
|------|------|------|------|
| 浏览器 | 一生一 persistent context；headless/headed 分别启动 | 用窗口显隐伪装模式 / 每份作业一浏览器 | 模式固定，停止释放后切换并复用 profile；扫码用程序内二维码；禁止补位 |
| 题库身份 | content_hash=题型+规范化题干+排序后选项集合；course_names 只追加不进 hash | 一门课一张表 / 用 ABCD | 选项打乱仍命中；跨课仍一行；作答只查 hash，超时 2 秒走 AI |
| 提交 | 页面两次 xcConfirm | 直接 POST | 站点脚本与扫码绑定 |
| 浏览器模式 | Playwright headless:true 与 headless:false 分别启动 | CDP、macOS 隐藏或同一上下文动态显隐 | 无头无窗口；可视化有窗口；运行中锁定，停止后重启 |
| 题库位置 | 云端一份 Supabase | 本机 SQLite | 用户要云端去重共用 |
