## 0. 执行边界

- 本文件定义目标 2/2 的任务、依赖、测试和证据；实现进度以 08/09 的分层证据为准，不把任务定义或内部测试写成整体验收完成。
- 无码答题使用独立工作模式值 `noqr`，旧账号缺失或非法值回退 `answer`。
- 无码登录、课程/作业检测、作答、保存、交卷、取分、重答、日志和异常状态必须落在独立 `electron/noqr/` 业务模块；目标 2/2 可按实际代码结构微调目录名，但不得把新站页面分支写入旧 `answer/extract` 业务函数。
- 旧 `answer`、`extract`、扫码、提交、批阅、题库回写和待回写补偿路径保持行为不变。工作台只允许增加模式选择、状态转发和现有控件接线，不得通过 UI 复用把业务逻辑混入旧模式。
- 新模块可以复制或复用不改变旧行为的纯函数、类型和稳定基础设施接口；旧模块不得 import 新页面选择器、运行状态或 `electron/noqr/` 实现。
- 共享基础设施只限账号读取、浏览器池、并发限制、日志通道、题库只读查询、AI 客户端和必要 IPC；每次共享改动都必须跑旧模式回归。
- 真实凭据只在目标 2/2 运行时读取，文档和日志只保留别名、计数和脱敏状态。

## 2. 预期模块职责

目标 2/2 预计新增独立的 `electron/noqr/` 业务目录；以下为建议职责，实际文件名可按现有项目风格微调，但职责和隔离边界不得改变。

| 预期模块/文件 | 职责 | 禁止 |
| --- | --- | --- |
| `electron/noqr/types.ts` | `noqr` 会话、课程、作业、题目、保存、分数和错误类型 | 不导入旧 `answer/extract` 业务状态 |
| `electron/noqr/selectors.ts` | 新站页面选择器、页面就绪和空白分类 | 不把新站选择器写进旧 `core/selectors.ts` |
| `electron/noqr/session.ts` | 登录页、首页就绪、会话复用、登录失败分类 | 不调用旧扫码授权/验证接口 |
| `electron/noqr/course.ts` | 形考作业、课程菜单、串行切课、课程范围、分页 | 不复用旧站课程深链或旧扫码闸门 |
| `electron/noqr/homework.ts` | 作业卡、日期/满分/次数、测试强制开关 | 不改变生产满分规则 |
| `electron/noqr/question.ts` | 题型识别、题目身份、子题/复合组解析 | 不按字母或默认第一项猜答案 |
| `electron/noqr/answer.ts` | 题库只读映射、AI 兜底、答案选择与读回 | 不调用任何题库写入 API |
| `electron/noqr/save.ts` | `SubmitJsonAsync`/`SubmitAllJsonAsync` L1/L2/L3 判定 | 不以 toast、遮罩或题号单独判定成功 |
| `electron/noqr/submit.ts` | 答题卡复核、漏题取消、`FinishJsonAsync`、成功证据 | 不把补保存当成最终交卷 |
| `electron/noqr/score.ts` | 记录接口、时间排序、分数和重答 | 不读取逐题对错，不写题库 |
| `electron/noqr/run.ts` | 无码独立运行编排、停止和异常隔离 | 不复制整段旧 `runner.ts` 业务分支 |
| `electron/workbench-coordinator.ts` | 按学生模式把开始、停止、选课和历史入口分发到旧 runner 或 `noqr/run`，并合并快照/锁 | 不承载新站页面细节，不让旧 runner import 无码模块 |
| `electron/core/work-mode.ts` | 中性的 `WorkMode` 类型和规范化函数 | 不 import 旧 runner 或 noqr 业务 |
| `src/views/HomeView.vue` | 仅第三模式按钮、配置显示和状态消费 | 不承载新站页面业务逻辑 |
| `electron/runner.ts` | 保留旧 `answer/extract` 调度和运行逻辑 | 不 import 无码模块，不新增无码页面条件或共享可变状态 |
| `electron/store.ts` / `src/useKaida.ts` | `noqr` 持久化值、旧值回退和 IPC 类型 | 不改变旧模式默认行为 |

## 6. TDD、命令与证据边界

### 6.0 证据等级

| 等级 | 定义 | 判定边界 |
| --- | --- | --- |
| E0 | 静态契约、依赖边界、版本/产物检查 | 只证明结构和静态边界 |
| E1 | 纯函数/node:test 回归 | 只证明解析、排序、状态机等局部逻辑 |
| E2 | 本地 Patchright 页面夹具，调用生产模块 | 只证明生产模块在可控外部边界的行为 |
| E3 | 内部 Electron 产品链，真实 Vue/Preload/IPC/调度 | 只证明产品接线，学校边界仍可为夹具 |
| E4 | 真实学校站点、真实产品按钮、无头浏览器 | 可证明无头真机 |
| E5 | 真实学校站点、真实产品按钮、可视化浏览器 | 可证明可视化真机 |
| E6 | 源码、Git、安装包和静态产物 | 不等于 Windows 真机或真实业务完成 |

只有 E4/E5 才能标记“真实真机通过”。E1/E2/E3 只能作为内部证据，E0/E6 不能替代产品验收。

### 6.1 目标 2/2 计划的 TDD 顺序

1. 先建立 `T005-00` 的静态隔离测试和页面夹具；故意在旧 `answer/extract` 加入 `noqr` 引用应失败，确认静态边界有效。
2. 对每个任务先写最小失败断言，再实现对应独立模块；不允许先写 UI 成功提示或固定返回值。
3. 保存/交卷必须有请求捕获和响应状态测试；只改变页面或 toast 的测试必须判失败。
4. 空白/慢响应/停止测试使用可控页面活动状态和请求生命周期，不把固定等待时长写成成功条件。
5. 题库零写入和旧模式回归每次全任务收口都要重复，不能只在最终阶段跑一次。

### 6.3 证据边界

- 真实证据：产品入口、真实新站域名、真实浏览器启动模式、真实保存/交卷/记录接口响应、真实页面状态，以及脱敏后的网络/队列计数。
- 内部证据：脱敏 DOM 夹具、可控 XHR、隔离题库读回和确定性时钟；只能证明生产业务函数如何处理外部边界，不能证明学校真实页面已通过。
- 静态证据：选择器、导入边界、禁止 API、旧模块反向 import 检查；不能替代运行结果。
- 失败证据：内部夹具、IPC、固定 HTML、固定成功函数、只看 toast/遮罩、只按页面题号或只按 DOM 顺序均为不足。
