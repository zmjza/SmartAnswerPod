# 开大自动答题桌面端 — Stitch 多页面设计提示词

额外设计约束：
（0）视觉风格整体要清爽明亮，禁止使用深沉压抑的配色（禁止米黄、奶油、深棕、暗金等暖旧色系，禁止纯黑或接近纯黑的深色背景），具体配色、排版、组件样式自由发挥，以轻盈、有光感、透气为方向。
（1）信息密度：每屏只有一个主角元素，其余全部降权；每个页面功能模块最多保留3个，超出的合并或隐藏到次级页面；列表每行只显示标题+1个状态+1个操作，禁止堆叠副信息。
（2）文字克制：每个组件内文字不超过2行；禁止在任何UI组件内出现段落描述、产品介绍、技术说明；禁止展示开发注释（路由路径、API标签、英文技术副标题、状态机标识）；导航菜单只显示标签名，禁止在菜单项下方添加任何说明文字。
（3）色彩纪律：全局强调色只用1个，状态色共用1套，总计不超过4色；优先级和分类差异用形状或位置区分，不新增颜色；禁止同一屏内同时出现超过2种状态色。
（4）层级与留白：用尺寸和留白区分主次，禁止所有模块等宽等高平铺；区域分隔靠留白完成，禁止用分割线或描边堆砌结构；主操作区、数据区、列表区之间留白不少于内容区高度的20%。
（5）一致性：全站所有页面共用同一套背景色、组件色、字体，禁止跨页面出现两种风格；每个视图只保留1个主操作按钮，其余收进溢出菜单；标签最多显示2个，其余折叠为+N。
（6）必须删除：一切以填充空间为目的存在的文字或图标；没有点击行为的装饰性元素；与页面标题或导航重复的区块标题；用户不会主动需要的系统运行信息。
（7）组件克制：禁止在同一屏内堆叠超过3种不同的组件形态；弹窗和抽屉只在用户主动触发后出现，禁止自动展开的浮层干扰主界面。
（8）空白保护：任何内容区域的填充率不超过70%，剩余30%必须保持空白；禁止为了看起来饱满而填充占位内容、示例数据或说明性文字。

> 本段为用户明确指定的强制设计约束，优先级高于本文其他视觉自主规则；Stitch 只在不违反本段的范围内自由发挥。

> 本段也优先于已确认文本视觉方案中的风格描述。视觉风格可以写入后文，但不得突破本段。

> 当前浏览器模式标准（2026-09-21）：无头模式使用 Playwright 真实 headless:true，不创建可见浏览器窗口；可视化模式使用真实 headless:false，窗口全程可见。两种模式均使用 channel:'chromium' 和学生持久化 profile，运行中禁止切换，停止后重新启动才能切换并复用登录态。二维码统一使用程序内“查看作业二维码”，不触发浏览器模式切换。本文历史生成内容中的旧扫码按钮、隐藏窗口和自动藏窗描述均以此标准为准。

> 用途：把本提示词整体交给 Google Stitch，完成本项目的全部页面视觉设计。占位内容必须已从 liran_docs 正式 PRD、功能树、模块文档、完整页面清单和已确认文本视觉方案填实。设计完成后请回传 Stitch Project Title、Stitch Project ID、Stitch Screen Name、Stitch Screen ID；Codex 再用 Stitch MCP 读取 HTML、样式、静态数据、图片、代码和 MD 规范，一比一落到真实前端 UI 壳，随后进入实例级细节复修。Stitch 不负责预留接口，不接真实业务逻辑。

- Stitch 根据项目业务、端形态、内容密度和可用空间自行决定设计系统、页面壳层、导航位置、布局和视觉风格；后文颜色、字体、像素仅为语义参考，不是固定模板。上述自主权不得突破文首额外设计约束。
- 普通设计决策、屏幕命名、变体补齐、预览和交付整理直接自主完成，不逐项询问用户。
- 页面数量不设置固定上限或下限。页面清单有几个页面，Stitch 就生成几个页面，不得遗漏，也不得自行增加。
- 独立路由或独立业务界面默认计为页面；弹窗、抽屉、面板、组件和 loading / empty / error / success 等状态默认归属对应页面，不额外计数。

- 若某模块与当前产品形态无关，直接标注不适用并说明原因。
- Stitch 不负责预留接口。完成后按第七节回传屏幕标识。

### 设计目标

- 不看 Chromium 窗口也能知道当前学生在登录、扫课、答题还是等扫码
- 任何时候都能看见题库答题数量和 AI 答题数量
- 四页风格一致，主按钮文案与字段和 PRD 第 10 节一致；顶栏导航四字：工作台、题库、学生账号、设置

### 必须出现的功能（布局由 Stitch 与用户微调，不得缺项）

页面仍是 4 个：工作台（主界面）、题库、学生账号、设置。不要第五页。不要内嵌完整浏览器。不要导出题库。不要收藏课入口。不要「授权直通」。不要限流开关。不要把无头/可视化放进顶栏。顶栏导航标签必须是「工作台」「题库」「学生账号」「设置」，选中为实心胶囊；本机状态只在工作台，不进这四个标签。

主界面必须能完成这些操作和展示：
- 顶栏：CPU%、内存%、本软件占用、浏览器数、压力 正常/偏高/过高；采集失败显示不可用。浏览器数=启动中+占用中+需验证占位，不含排队。
- 多学生：学生账号页添加；工作台学生卡切换当前学生。第三人排队时该生卡片能看出排队中，顶栏浏览器数不因排队增加。
- 左列我的课程：按门户顺序。每行课程名+1 个状态。状态至少要能表现：检测中、无作业、已检测、满分跳过、权重0跳过、非客观题跳过、窗口外、次数用尽、需验证、待答题、回填中 x/y、题库答题 x、AI 答题 y、已提交、待回写、登录失败、提交失败、未满分下次再做、提取中、已提取、检测失败、排队中。
- 中列当前课分成「网上记分作业」「阶段性测验」两组。标题旁固定题库答题 x、AI 答题 y。标题下固定当前题来源，必须能表现三种：当前第 12 题 · 题库答题；当前第 12 题 · AI 答题 · GLM-5.3；当前第 12 题 · 空过。作业行：作业名+1 个状态。一组暂无数据则该组一行暂无数据。悬停才出每题题号、来源（题库答题 / AI 答题 / 空过）。作业状态至少：权重0跳过、非客观题跳过、窗口外、次数用尽、满分跳过、待做、预览中、闸门排队、点做作业、需扫码、作答中、提交中、提交失败、等批阅、校对中、待回写、100分结束、未满分下次再做、空转提前停、提取中、已提取。
- 学生卡右上角：无头浏览器 | 可视化浏览器。
- 学生卡工作模式：答题 | 提取题库。答题=检测完自动开答，交卷后自动校对入库。提取题库=同一主按钮只上号抽已批阅卷，不点做作业、不提交。
- 主句=账号中文状态+当前动作，禁止只写进行中。例句必须能出现：空闲；排队中等待浏览器名额；启动该生浏览器；登录 IAM；登录失败；需验证 · 查看作业二维码；需验证 · 等待验证确认；已登录确认我的课程；扫课 2/6；打开课程；点形考作业；读网上记分作业；读阶段性测验；预览某作业；闸门排队等本号扫码；点做作业；第 12/40 题题库答题；第 12/40 题 AI 答题并带模型名；提交作业等确定弹窗；提交失败；等批阅；校对中；待回写补抽；本轮结束；已停止；提取题库抽已批阅卷。
- 姓名；学号、专业、分校可空。账号并行、课程并行。日志、停止、删除。删除先停再从本机列表拿掉；课程重新检测统一使用底部“登录并刷新课程”。
- 无头需验证：查看作业二维码 + 验证完毕，浏览器继续隐藏。可视化需验证：窗口保持可见并提供查看作业二维码 + 验证完毕。IAM 验证码和人脸共用这一套暂停，不另做一套按钮。
- 日志：逐步列出每次点击或跳转，点开才出现，不要自动弹层。
- 底栏：答题模式显示课程 i/N 与待做完成数；提取题库模式显示课程 i/N 与已提取份数。唯一主按钮文案必须是「登录并刷新课程」。占用中再点则先停再重测。不要在桌面端放「提交作业」按钮，交卷由程序自己做。
- 可出现更新提示：有更新、安装、稍后、检查失败；不另计页面，失败不影响答题。

学生账号页必须有：账号列表（姓名、掩码账号、删除）；手工添加（姓名、账号、密码，可见 label）；Excel 导入三列姓名账号密码且跳过表头，缺列或空文件提示格式错误；添加成功一句；占用中删除先停再释放名额。不要 Key。不要并行开关。不要 service role。

设置页必须有：硅基流动 Key（可更换，默认空）；Supabase URL；anon key；账号并行默认 2；课程并行默认 2；浏览器默认模式；日志默认开；保存；校验失败一句；加密失败不能保存明文的提示。不要账号列表。不要 Excel。不要 JSON。不要 service role 输入框。无头=Playwright headless:true 且无可见窗口；可视化=Playwright headless:false 且窗口可见；运行中锁定，停止后重新启动才能切换；改默认只影响尚未启动的学生。

题库导入页必须有：选择 JSON、导入、新增 n、合并 n、冲突 n、缺字段跳过 n。不要导出。不要登录。不要扫课。从开大抽题只走工作台学生卡提取题库模式。

### 不在范围内

- 不生成完整页面清单之外的页面、弹窗或后台模块。
- 页面数量不设置固定上限或下限。页面清单有几个页面，Stitch 就生成几个页面，不得遗漏，也不得自行增加。
- 独立路由或独立业务界面默认计为页面；弹窗、抽屉、面板、组件和 loading / empty / error / success 等状态默认归属对应页面，不额外计数。
- 如果 Stitch 单次无法生成全部页面，可以分批生成；所有批次最终必须覆盖完整页面清单，页面总数、名称、职责和关系不得漂移。
- 不擅自改变业务角色、字段含义、状态流转或页面数量。
- 不把多个独立页面合并成一个含糊的长页面；需要变体时单独命名屏幕。
- 不预留真实接口、不写业务逻辑、不把 UI 壳说成业务完成。
- 不生成 H5、小程序、登录站点页、作答站点页。
- 不要把无头浏览器与可视化浏览器切换放进顶栏。
- 不要用真实姓名学号密钥；假数据只用张同学、李同学和全 0 学号。
- 不要画完整内嵌浏览器。
- 不要提供题库导出按钮。
- 不要视障学生做作业入口。
- 不要画开大站点的提交确认框、微信扫码二维码、作答页题目。扫码在学生卡上只出「查看作业二维码」和「验证完毕」。
- 不要续做按钮。不要收藏课。不要限流开关。不要授权直通。

## 四、每个屏幕的详细设计要求

### PC-P01 — 主界面

1. **屏幕元数据**：PC 端；Stitch 屏幕名称 PC-P01-home；1440 x 900 横向；路由 / ；管理员；启动即进入；无返回。
2. **布局骨架**：无侧栏。顶栏高 48 固定。中区三列：左科目宽 280，中客观题结果自适应且为视觉主角，右学生卡宽 320。底栏高 72 固定。列间距 24，页边 24。中区与底栏之间留白至少 16。
3. **视觉层级**：第一主角是中列当前课客观题结果；第二是右侧学生卡主句；第三是底栏主按钮「登录并刷新课程」；顶栏本机状态降权为单行胶囊。
4. **组件清单**：顶栏四字导航（工作台/题库/学生账号/设置）、本机状态文本、学生切换、课程列表行、结果列表行、悬停浮层（用户悬停才出现）、学生卡、两组分段开关、胶囊计数、进度条、主按钮、停止/刷新/删除/日志、扫码按钮、日志面板（用户点日志后才出现）、更新提示条、空态、骨架。不要表格、不要题型 Tabs、不要自动弹窗、不要内嵌浏览器。
5. **字段/列定义**：CPU 百分比、内存百分比、本软件占用、浏览器数（只计 launching + occupied + occupying_verify，不含排队）、压力 正常/偏高/过高。左列课程名 + 1 个中文状态。中列分「网上记分作业」「阶段性测验」两组，作业名 + 1 个状态；标题旁固定题库答题 x、AI 答题 y；标题下固定当前题来源。学生卡上方学生切换。学生卡：右上无头浏览器/可视化浏览器；其下第二组分段开关「答题 | 提取题库」，这就是独立提取题库入口，不是独立页面，也不放在题库导入页；第四页是学生账号。主句=账号中文状态+当前动作；下一行题库答题 x 与 AI 答题 y，提取模式下也要在。姓名学号一行；专业分校一行；账号并行、课程并行两个芯片；日志、停止、删除。扫码入口为「查看作业二维码」；无头保持隐藏，可视化保持可见；验证成功前不恢复队列。答题模式点「登录并刷新课程」后检测完自动开答。提取题库模式同一主按钮只登录扫课并抽已批阅卷，不点做作业、不提交。自动提取随答题校对入库，不另开页面。底栏答题模式为课程 i/N 与待做完成数，提取模式为课程 i/N 与已提取份数。不要桌面端「提交作业」按钮。更新提示：有更新、安装、稍后、检查失败。
6. **真实语义数据**：答题态课程五行：社区管理实践 / 已检测；社会保障理论与实务 / 回填中 12/40；形势与政策 (1) / 已检测；社会工作实务 / 无作业；社区矫治基础 / 待检测。提取态同一五行改为已提取 / 提取中 / 已提取 / 无作业 / 待提取。网上记分作业两行：记分作业一 / 已检测或已提取；记分作业二 / 回填中或提取中。阶段性测验一行暂无数据。悬停记分作业一含三题来源：题库、AI、空过。学生切换：张同学 000000000001 占用中，李同学排队中。示例专业，示例分校。画面按 70% 空白裁切，不要把五行全挤满。
7. **交互流程**：点左列切换中列。悬停作业行才出每题来源。点学生名切换当前卡。点「登录并刷新课程」主按钮有按下态，不跳站点；占用中再点先变为已停止再重测外观。点无头/可视化只选择下一次启动模式，不在运行中动态显隐；运行中锁定，停止后才能按新模式重新启动。点答题/提取题库只改该卡工作模式并改主句和底栏文案（待做改已提取）。点日志才出日志面板。点停止主句变为已停止。点删除该生从列表消失。需验证时点「查看作业二维码」打开程序内二维码；点「验证完毕」先复核页面成功态再恢复队列。更新条点稍后收起；检查失败时条上只留「检查失败」。顶栏四字切到题库、学生账号、设置。
8. **状态变体**：加载时顶栏数字为破折号、列表骨架；空课程「还没有课程」；错误一行珊瑚；采集失败对应项显示不可用；压力正常/偏高/过高；需验证无头双按钮；需验证可视化单按钮；排队中无扫码按钮；正常作答主句例如「自动开答 · 第 12/40 题」；提取题库主句例如「提取题库 · 抽已批阅卷」；登录失败；提交失败；待回写；已停止；更新条可见、已收起或检查失败。状态变体不计入基础页面数，不要自动展开浮层。
9. **端内适配规则**：仅 1200 到 1440 宽。窄时中列优先，左右列不要等宽平铺。
10. **可访问性**：主按钮可 Tab；开关有选中态；计数不只靠颜色，题库实心、AI 空心；对比度达到可读。

2. **布局骨架**：无侧栏。中央一块设置卡，最大宽 560。模块不超过 3：连接、运行默认、保存反馈。
3. **视觉层级**：主操作只有「保存」。
4. **组件清单**：顶栏四字导航、密码输入、文本输入、数字输入、开关、保存主按钮、成功一句、加密失败一句。不要账号列表。不要 Excel。不要 JSON 导入。

7. **交互流程**：保存成功湖绿一句。加密失败珊瑚一句。改浏览器显示只影响尚未启动的学生。
8. **状态变体**：校验失败、保存成功、加密失败。不要自动弹窗。
9. **端内适配规则**：始终居中卡片，不要拉成全宽表。
10. **可访问性**：每个输入有可见 label；密码可遮罩。

### PC-P03 — 题库导入

1. **屏幕元数据**：PC 端；PC-P03-bank-import；1440 x 900；/bank；管理员；顶栏题库进入；无返回按钮。

5. **字段/列定义**：文件名、新增 n、合并 n、冲突 n、缺字段跳过 n。去重按题干加排序后选项集合，选项顺序打乱仍合并。JSON 每项含题型、题干、选项正文数组、正确选项正文数组。本页只接收本地 JSON。从开大自动上号抽题不在本页，必须回到工作台学生卡切「提取题库」再点「登录并刷新课程」。
6. **真实语义数据**：questions.json；新增 12；合并 4；冲突 1；跳过 2。空态「还没有导入过题库」。
7. **交互流程**：先选文件再导入。成功显示四个数字：新增、合并、冲突、跳过。失败一行珊瑚。不要在本页画登录、扫课或提取进度。
8. **状态变体**：空、导入中、成功、失败、冲突大于 0。
9. **端内适配规则**：始终居中卡片，不要拉成全宽表。
10. **可访问性**：导入按钮有明确 label；数字旁有文字「新增」「合并」「冲突」「跳过」。

### PC-P04 — 学生账号

1. **屏幕元数据**：PC 端；PC-P04-accounts；1440 x 900；/accounts；管理员；顶栏学生账号进入；无返回按钮。

10. **可访问性**：每个输入有可见 label；密码可遮罩；删除需能键盘到达。

## 五、端与页面类型补充要求

### 门户/用户中心

不适用：当前任务不是网站门户，原因是这是 Electron 桌面操作台，入口是 App 启动和页内文字导航。

### 业务管理后台/超级管理员后台

不适用：当前任务不需要侧栏菜单、分页表格、角色权限矩阵。原因是四页工作台已经覆盖进度、题库导入、学生账号和设置。

### 移动端（统一包含 H5/微信小程序）

不适用：当前任务移动端 0 页，原因是只做 macOS 与 Windows 桌面窗口。

## 六、Stitch 执行顺序

1. 在同一个 Stitch 项目中先建立统一设计系统和组件基线。
2. 先完成 PC 端 PC-P01-home、PC-P03-bank-import、PC-P04-accounts、PC-P02-settings。
3. 本项目只有 PC 端，不要生成移动端屏幕。
4. 需要状态变体时保留可切换 variant 或附属屏幕名，如 PC-P01-home-verify-headless，不计入基础 4 页。
5. 完成后核对 PC 4、移动 0、总数 4；不要删除设计记录或用响应式变体减少数量。

请按 Stitch MCP 口径提供以下信息，缺一项就不能声称 Stitch 设计已完成：

- Stitch Project Title
- Stitch Project ID 或项目链接
- 全部 Stitch Screen Name、Stitch Screen ID、所属端、对应页面编号和路由

- 设计中未表达的业务交互、字段或权限规则，以正式 PRD / 模块文档为准并单独标记

核对门禁：

- PC 端计划页面数 = PC 最终版屏幕数；
- 移动端计划页面数 = 移动端最终版屏幕数；
- 项目总页面数 = PC 端独立页面数 + 移动端独立页面数；
- H5 与微信小程序共享的移动页面只计一次，每个移动页面均已标明适用平台；
- 每个最终版屏幕都能被 Stitch MCP 按屏幕 ID 读取；
- 任一项缺失或仍是草稿时，继续补齐，不得称为完成。
