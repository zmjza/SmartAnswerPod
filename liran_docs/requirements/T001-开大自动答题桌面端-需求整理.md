## 用户想解决的问题

上海开放大学管理员要做一个自己用的桌面自动答题器：登录学习平台，按课程扫形考作业（网上记分作业 + 阶段性测验），客观题用「自己题库优先、没有再 AI」作答并提交，再把 AI 答对的题回收进题库。最终尽量全程只用自己题库。

## 目前讨论内容

### 提出

- 形态：Electron 桌面端，mac + win，GitHub OTA。
- 浏览器自动化：Playwright 无头，多并发也要单并发。
- App 里每一步点击都要看得见进度。
- 登录：账号密码，复刻已有谷歌插件自动上号。
- 课程：只扫「我的课程」，按顺序打开，先点形考作业。
- 作业判定：两块列表；暂无数据=无作业；客观题权重>0 要做；客观题 0% 不做；非客观题要做。
- 预览页：看历史分数；点做作业；第一次可能微信扫码，无头必须暂停改可视化，用户点验证完毕再继续。
- 作答页：已有根目录结构文档，单选/多选/判断，答完自动提交。
- 题库：人工上传 + 从已作答学生卷提取；存放位置待定。
- AI 题提交后去历史「查看」校对，对的写入题库。

## 已确认的内容

- 产品是桌面 App，不是浏览器插件本体（插件只提供登录复刻来源）。
- 平台：mac + Windows。
- 更新：GitHub OTA。
- 自动化引擎：Playwright；无头使用真实 headless:true 且不创建浏览器窗口，可视化使用真实 headless:false 且窗口全程可见。扫码统一使用程序内二维码和「验证完毕」，不因扫码切换模式。
- 学生卡片右上角可切换「无头浏览器 / 可视化浏览器」，每个学生独立。切到可视化则该生登录、检测、答题、扫码、提交全程可见，弹码不必再点「打开可视化浏览器」，验证完毕不藏。切回无头立刻藏，之后仍走上一句无头规则。禁止把该按钮放进顶栏 CPU 那一行。禁止 headless:true 再切 headed。
- 并发：要支持多并发和单并发。
- 进度：App 内实时看到每一步网页点击在干什么。
- 主界面信息架构（参考用户截图，正式视觉更精致，不照抄糙样式）：顶栏机器状态（CPU/内存/软件占用/浏览器数/压力）；中间左列科目、右列该课客观题检测/作答状态（无作业、检测中、已检测、答题准备中 x/y、待答题准备等，悬停可看细节）；右侧当前学生卡片（姓名、学号、专业、分校、模式、账号并行/课程并行、浏览器显示、限流、日志、刷新/删除）；底栏总进度条；主按钮「登录并刷新课程」；可添加多个学生账号。不内嵌完整浏览器。默认隐藏窗口。扫码时卡片出「打开可视化浏览器」，程序不自动弹窗；用户点了才显示该生窗口；点「验证完毕」后默认自动藏回去。一个账号卡在扫码时其它已占名额的账号继续。
- 学生卡片右上角放「无头浏览器 / 可视化浏览器」切换，不要放进顶栏。无头模式仍按上一句扫码显隐。可视化模式该生窗口一直显示，弹码不必再点打开，验证完毕不藏；切回无头立刻藏。
- 顶栏本机状态用途：让用户自己看还能加多少并发。至少显示 CPU%、内存%、本软件占用、当前浏览器/上下文数量、压力档位（正常/偏高/过高）。压力只做展示和告警，第一期不自动限流（参考图「限流」默认未开启）。
- 课程范围：学习门户「我的课程」，按 DOM 顺序。
- 形考入口：`#courseHomeWorkNew`「形考作业」。
- 只处理两块：网上记分作业列表、阶段性测验。
- 无作业：标题「…：暂无数据」。
- 客观题 + 权重>0：要做，点「查看」。
- 客观题 + 权重=0%：标记不需要做。
- 非客观题 / 主观题：第一期不做，只标记跳过。原先「非客观题要做」推迟。
- 不走「视障学生做作业」。
- 作答策略：题库优先，没有才 AI。每题标记来源，界面必须额外显示「题库答题」和「AI 答题」（数量 + 当前题来源），不能只记内部日志。
- 第一期只做「网上记分作业 + 阶段性测验」里的客观题且权重>0。课程实践、资源学习、直播面授、主观题第一期都不做。
- 作答历史里已批阅且分数为 100：跳过，不再做、不再提交。
- 未完成提交 / 有「续做」：不点续做，点「做作业」新开。
- 提交：程序只提交整卷复核完整的作业，不等用户在 App 里再点一次。正常“作业提交后将不可修改”确认点深蓝确定；出现未作答警告必须点绿色取消并补答，禁止提交漏题卷。
- AI：硅基流动，设置页填/换 API Key，本机加密保存，禁止入库。按顺序降级，一个模型失败或格式不对就换下一个，全部失败才记「AI 失败」并继续。顺序：1) `deepseek-ai/DeepSeek-V4-Flash` 2) `zai-org/GLM-5.3` 3) `Pro/moonshotai/Kimi-K2.6` 4) `Qwen/Qwen3.8-27B` 5) `tencent/Hy4-preview` 6) `stepfun-ai/Step-3.5-Flash`。开发时按硅基流动控制台核对 id。
- AI 输出：固定提示词，只允许一种结构化结果（推荐 JSON：`{"option_texts":["正确选项正文",...]}`）。禁止只回 A/B/C/D。解析失败视为该模型失败，换下一个。回填仍按选项正文点当前页。
- 密钥：学生账密、SiliconFlow Key、Supabase Key 都在设置页填，本机 `safeStorage` 加密，不进 git、不写进安装包。
- 收藏课程：不扫。
- 使用对象：自己和朋友。每人自己的安装里填 Key，安装包不含密钥。第一期仍可直连 Supabase；不要把 service role 写死进客户端代码。
- OTA：electron-updater + GitHub Releases，当前这个仓库。
- 技术栈：Electron + Vite + TypeScript + Vue3；Playwright 在主进程；登录从自动上号器扩展搬改，不把扩展嵌进 App。
- 并发：多个学生账号同时跑；每个账号内部多门课同时跑（账号级并行 × 课程级并行）。也要能切成单账号单课。
- 形考范围按学生隔离：登录哪个学生，就只做该生「我的课程」里网上记分作业 + 阶段性测验的客观题（权重>0）。不是公共卷，也不是操作员自己的课。
- 每个学生独占一个 Playwright 浏览器（一份 userDataDir）。同一号多份作业只开标签，不开第二个浏览器。
- 账号并行名额：取得名额才开浏览器。扫码/验证码暂停、等批阅都不释放名额。禁止暂停后把名额让给排队学生补位。「其它号继续」只指已经占到名额的号。
- 默认模式是无头：该生使用真实 headless:true 且没有浏览器窗口。可视化模式使用真实 headless:false 且窗口全程可见。学生卡片选择的是下一次启动模式；运行中锁定，停止释放后才能切换并重新启动，继续复用 profile 和登录态。扫码不触发模式切换，统一使用程序内二维码。
- 题库：Supabase 云端，所有学生账号共用一份。本机不作为主库。密钥和 SiliconFlow Key 一样走设置页，禁止入库。
- 题库身份：题型 + 规范化题干 + 规范化后的选项正文集合。选项只是顺序打乱、集合相同 → 同一题，不得存成两条。字母、data-index 不参与身份。
- 题库去重：手动导入、开大提取、AI 校对回写走同一条 upsert。`content_hash` 对上面的身份做唯一约束，重复行合并。
- 去重规范化：去首尾空白、合并连续空白、全角转半角、去掉题号前缀（如 `1.` `1、`）、选项去掉 `A)` `A、` `A.` 前缀后再比正文。判断题选项统一成正确/错误。
- 答案存储：存「正确选项的正文」（多选存正文列表），禁止把 A/B/C/D 或 `data-index` 当标准答案。同一题下次 B 调到 A，库里仍是那段选项文字。
- 答案回填：命中后在当前页选项里按正文找对应 `li.e-a`，点它的 `data-index`。单选点一个；多选把库里每个正确正文都点上。不要按上次的字母或 index 去点。
- 答案冲突：已验证正确答案优先；未验证 AI 草稿不能覆盖已验证答案；两边都是已验证但正文答案不同则留旧值并记冲突。
- 答题匹配：现场题用同一套身份算 hash，精确命中才用库；第一期不做模糊搜。未命中才 AI。
- 每次提交并已批阅后都去最新记录「查看」校对：AI 答对入库，题库答错删除。
- 作答页契约以 `开大自动答题页面结构.md` 为准。
- 页面结构按页拆 md，以后改结构只改对应文件。

### 闭环补全（第七轮建议默认，视为已确认）

工作流拆成两段，主按钮「登录并刷新课程」只做检测；检测完成后自动开答，不再让用户点第二次。
答题过程中课程行、悬停明细和该号进度都要能看出「题库答题」还是「AI 答题」，以及各自题数。

1. 检测：每账号登录门户 → 只扫「我的课程」→ 按 DOM 顺序进课 → 点 `#courseHomeWorkNew` → 只读 `#onlineHomework` 与 `#phasedTest` → 要做的行点「查看」进预览，判断满分/窗口/次数。检测阶段不点「做作业」。一门课两块扫完再下一门；多账号、每账号多课按设置并行。
2. 答题：先按该份作业的可答次数决定当次最多提交几轮。每轮点「做作业」新开 → 题库命中则回填，否则 AI → 提交闭环 → 已批阅后「查看」校对（AI 对的入库，题库错的删除）。到 100 立刻停；否则按当次上限再新开。其它课/其它号仍并行。

检测判定（预览页 + 列表行一起看）：

- 两块都「：暂无数据」→ 无作业。
- 客观题权重 = 0% → 跳过（不需要做）。
- 非客观题 / 未知题型行 / 课程实践 / 资源学习 / 视障 → 第一期跳过并标记。
- 已批阅且分数 = 100 → 整份跳过，不再做。
- 已批阅但 < 100，或未完成提交 / 未提交记录 / 有续做 → 不点续做，列入要做；点「做作业」新开。
- 当前时间早于形考开始或晚于形考结束 → 窗口外跳过，不要硬点。
- 答题前必须先判定可答次数，不要一上来连刷。来源：列表「作答次数」可见文案（如 `1/无限制`、`2/3`）和 hidden `replyCount`。文案含「无限制」或 `replyCount=-1` → 无限制。有上限时剩余 = 上限 − 已用；解析不到已用则剩余按上限算。剩余 ≤ 0 → 次数用尽，跳过。
- 当次提交上限（到 100 立刻停，不必用满）：
  - 无限制：当次最多 10 次。
  - 有限制且上限 ≤ 3，或剩余 ≤ 3：当次最多 1 次（省次数）。
  - 有限制且剩余 > 3：当次最多 min(10, 剩余)。
- 每一轮：点「做作业」新开（不续做）→ 答完提交（见提交闭环）→ 等最新已批阅 → 打开「查看」校对：AI 答对的入库；题库答错的从题库删除。不是 100 且未打满当次上限，再新开一轮。被删掉的题下一轮当未命中，走 AI。
- 打满当次上限仍不是 100：离开这份，记「未满分，下次再做」。下次「登录并刷新课程」若仍不是 100 且还有剩余次数，再按同一套上限新开。
- 每一轮必须先已批阅并校对完成，才允许新开下一轮。批阅超时或打开查看失败：这份记待回写，当次停止连刷，不得未删错题就再答一遍。
- 防空转：逐题阶段 AI 全失败先记失败；提交前补答允许再执行一次模型降级。仍失败或未知题型无法作答时停止该份且不提交。题库答错已删除后不算空转。若新一轮分没涨、库没有删题也没有新入库则提前停。用户停止或窗口结束同理。
- 最终目标仍是 100 分：靠有限连刷 + 自动提取让题库越积越全，后续运行再凑满分。

登录与会话：

- 登录复刻自动上号器：IAM `iam.shou.org.cn` 填学号/账号和密码并提交 → 进 `learning.shou.org.cn/scenter`。若停在 `/login` 再跳 scenter。

- 中途会话过期：该号重走 IAM；连续失败则停该号。

- 是否已验证以页面是否弹出「微信扫码验证」为准，不要每次都假设要扫。已验证过的账号再点「做作业」应直接进作答页。
- 参考图「授权直通」含义信息不全，第一期不当特殊通道，普通作业走扫码逻辑。

同一账号扫码闸门（多作业并行的正确做法）：

- 站点把扫码结果放在该学生会话的 localStorage（`validateResult_` + 学号后缀）。所以**同一个学生账号必须共用一个 Playwright BrowserContext**（同 cookie、同 localStorage）。不同学生用不同 Context。禁止给同一号的每份作业各开一个隔离浏览器，否则扫一次等于没扫。
- 检测阶段可以并行打开多份作业的预览页（`assignment-preview.aspx`），预览不弹码。
- 答题阶段按账号加闸门：该号尚未验证时，**同时只允许一份作业点「做作业」**。同一号其它作业停在预览页排队，不要一起点，避免一次开 3 个码。
- 第一份弹出「微信扫码验证」：暂停该号，提醒用户，卡片上「打开可视化浏览器」。用户扫完点「验证完毕」（或页面已出现进入作答/弹窗消失）→ 该号标记已验证。
- 已验证之后：对该号**已经打开的其它预览页全部刷新**，再点「做作业」。不要对着旧的扫码弹窗点。刷新后 `doHomework` 会读到已验证，不再弹码。
- 若闸门没拦住、已经弹出多个码：只让用户扫当前可视化那一个；其余弹窗取消，预览页刷新后再点「做作业」。禁止要求用户扫三次。
- 扫码有效期：站点大约 2 小时内同一学生会话不再弹码（localStorage `validateResult_`）。**以页面为准**：点「做作业」弹了「微信扫码验证」才扫；没弹就直接进作答。禁止用程序自己的 2 小时计时去跳过 `doHomework` 或直接 `goto` 作答页。
- 为让这 2 小时在 App 里也成立：每个学生账号在本机持久化一份浏览器用户目录（cookie + localStorage），该号一直复用。App 重启、换课、换作业，只要站点还认这次验证，就不再扫。用户目录不进 git、不进安装包、不进题库。
- 约 2 小时过了、用户目录被清、或换了隔离 Context：再点「做作业」会再弹码 → 再走同一套闸门（暂停、可视化、扫一次、刷新该号其余预览）。不要假定一次扫码管一整天。
- 进度可写「已验证，约 2 小时内免扫」，只给用户看，不作放行依据。
- 该号已验证且页面不弹码时，后续作业直接点「做作业」。若仍弹码：先刷新预览再点一次；还弹则再走扫码暂停，不要死循环。
- 课程并行、连刷新开都走这套闸门。其它学生账号不受影响。

作答页：

- 只处理 `data-questiontype` 1 单选、2 多选、3 判断。其它题型标记受阻并停止该份，不要用未知结构猜测，也不得提交空题。
- 点 `li.e-a[data-index]`，以该题 `[name=answer]` 非空为已做。
- 多选必须把库里每个正确选项正文都点上。
- 判断题按选项正文「正确/错误」点；`data-index` 1=正确、0=错误，禁止用 A/B 推 index。
- 右侧已做看 `a.e-item.active`。
- 点下一题前确认本题已保存；提交走下面的提交闭环，不要只点按钮不管结果。

提交闭环（成功只认作答历史，不认弹窗关了）：

- 提交前记下该份预览页历史里最新一条的提交时间。
- 点 `#submitHomeWork`，等深蓝确定弹窗（`a.sgBtn.ok`）。约 8 秒没有弹窗：再点一次提交；还没有 → 提交失败。
- 提交前同时检查隐藏答案值、完整答案集合和右侧已做题号；漏题最多补答 30 轮，每轮显示轮次、剩余题号和失败原因。正常确认点深蓝确定；若出现「未作答视为错误」必须点绿色取消，回到补答流程；第 30 轮仍补不齐则安全停止并明确显示未提交。
- 等跳回 `assignment-preview.aspx` 并刷新历史。成功 = 出现一条提交时间比提交前更新的记录。不要只看弹窗消失。
- 失败：记「提交失败」，这份当次停止连刷，其它作业继续。历史没有新行就不算用掉一次作答次数。下次刷新再做。
- 禁止提交失败还当成功去校对、去扣次数、去连刷。

题库（云端一份，全账号共用）：

- 用 Supabase。云端共用 + 去重 upsert 一张表就够，不自建库、不放本机主库。
- 朋友各自在设置里填同一套 project URL + anon key。禁止 service role 进客户端、进 git、进安装包。anon 泄露等于题库可被读写，第一期接受（自己和朋友）。
- 最小表 `questions`：`qtype`（single/multiple/judge）、`stem`、`options` jsonb、`answer_texts` jsonb、`content_hash` unique、`course_names` text[]、`source`（import/extract/ai_verified）、`verified`、`conflict`、`updated_at`。禁止按课拆表。
- 身份：题型 + 规范化题干 + 规范化选项正文集合（排序后）。选项顺序打乱仍是同一题。字母、data-index、课程名不参与身份。作答只查 content_hash，超过 2 秒当未命中。
- `course_names`：出现过的门户课程标题。同一题跨课追加去重。JSON 导入无课程名则空数组。只给以后检索，不作答过滤。
- `content_hash` = 上述身份的 hash，导入 / 提取 / AI 校对同一条 upsert。
- 答案只存正确选项正文（多选存正文列表）。回填按当前页正文找 `li.e-a` 再点它的 data-index。
- 已验证答案不被未验证稿覆盖；两边都已验证但答案不同：留旧并 `conflict=true`。
- AI 题只有批改后确认正确才入库；答错不写。题库答对的不必回写；题库答错的删除。
- 第一期精确命中，不做模糊搜。Supabase 读失败当作未命中改走 AI；写失败记待回写，不卡死其它任务。

题库导入与提取（自动答题之外必须有，否则几百学生旧卷进不了库）：

- 设置或独立「题库」页：导入 JSON。每项含 qtype（single/multiple/judge）、stem、options 正文数组、answer_texts 正确选项正文数组。
- 不提供导出（云端就是备份）。
- 提取分两种，都要有：
  - 独立模式：学生卡片选「提取题库」。登录该生 → 课程 → 形考两块 → 预览里所有已批阅「查看」→ 从 `history.aspx` 抽题干/选项/正确项 upsert。不点做作业、不提交。
  - 自动模式：答题模式下，提交并已批阅后校对整份。AI 答对且题库没有则入库；AI 答错不入库。题库答错则删除该题。
  - 题库答错过也要查：批改证明题库那条是错的，按 content_hash 从题库删除。当次后续轮次视为未命中，改走 AI。不要留着继续命中错答案。
- 学生卡片模式两个：答题（默认，含自动提取）、提取题库（独立模式）。
- `history.aspx` 开发到提取/回写模块时，由 Codex 带着用户打开该页补页面结构，补完再写抽取代码。禁止先猜 DOM。

AI：

- 硅基流动，设置页填 Key。14 个去重模型按序降级，失败或 JSON 不对就换下一个；单轮全挂时主界面显示题号、尝试数和最终原因，提交前最多补答 30 轮，第 30 轮仍失败则安全停止该份并显示未提交。
- 顺序：1) deepseek-ai/DeepSeek-V4-Flash 2) deepseek-ai/DeepSeek-V4-Pro 3) zai-org/GLM-5.3 4) moonshotai/Kimi-K2.7-Code 5) Qwen/Qwen3.8-27B 6) stepfun-ai/Step-3.5-Flash 7) tencent/Hy4-preview 8) Qwen/Qwen3.6-35B-A3B 9) Qwen/Qwen3.6-27B 10) Pro/deepseek-ai/DeepSeek-V3.2 11) deepseek-ai/DeepSeek-V3.2 12) zai-org/GLM-5.2 13) Pro/zai-org/GLM-5.1 14) Pro/moonshotai/Kimi-K2.6。开发时对硅基流动控制台核对 id。所有模型共用统一高校课程客观题提示词，不因题目主题拒答。
- 只收 `{"option_texts":["正确选项正文",...]}`。禁止只回 A/B/C/D。
- 提交成功后轮询预览历史最新一条变为「已批阅」再点查看。AI 答对的入库；题库答错的删除。
- 「待回写」的意思：卷已经交了，但批阅还没出来（或打开查看失败），所以还没把 AI 对的题写进题库、也还没删题库错题。超时先记下这份作业的待回写，该份当次不得再新开，不卡死其它任务。下次该号检测或答题时先把这些待回写补抽补删，补完再决定要不要新开，不要丢。

## 当前验收想法

- 设置可保存账密和三 Key（本机加密，仓库搜不到真实值）。
- 登录并刷新后能列出「我的课程」门数与名称；收藏课不出现。
- 能识别：无作业 / 要做 / 0%跳过 / 非客观题跳过 / 100分跳过 / 窗口外 / 次数用尽。
- 检测阶段不点「做作业」；答题阶段不点「续做」。
- 作答页按题型点选项，多选能多选，判断按正确/错误正文，右侧题号提亮，answer 有值。
- 同一题选项顺序打乱仍命中，回填点的是当前页正确正文，不按 A/B。
- 扫码时该号暂停并继续占浏览器名额，已占用的其它号继续，排队号不得补位。同一号多份作业只扫一次；扫完刷新其余预览再做。约 2 小时内免扫，过期再弹码再走闸门。
- 默认无头：弹码窗口仍隐藏，用户点「打开可视化浏览器」才显示该生窗口，点「验证完毕」后自动再藏。卡片右上角切到可视化后该生全程看得见，弹码不必再点打开，验证完毕不藏；切回无头立刻藏。切换按钮不在顶栏。
- 答完走提交闭环：弹窗确定后，以作答历史出现新记录为成功。失败重试点击，仍失败不扣次数。到 100 停；无限制当次最多 10 次，3 次及以内当次最多 1 次。
- 进度区能看到每一步在点什么；顶栏能看到 CPU/内存/浏览器数。
- 主界面能按五层状态机看到：排队/启动浏览器、登录 IAM、课程 x/N、检测第 i 门、哪份作业第几题、题库还是 AI、扫码占位；不能只有一个「进行中」。
- 进度和课程行能看见「题库答题」和「AI 答题」的数量与当前题来源。
- 题库命中与 AI 分别记账；AI 答对入库，题库答错从题库删除；重复导入不新增行。
- 独立提取模式只抽已批阅、不提交；答题模式提交后自动校对 AI 题。
- 未知题型或 AI 全挂且补答仍失败时停止当前作业，不提交漏题卷。
