## 1. 产品/功能概述

同一个程序自动适配旧版学习中心和新版未来学习空间。新版新增首页进入学习、逐课获取形考入口的路径，两版最终进入既有形考作业页并共用后续检测流程。

## 2. 背景与问题

学校按账号逐步启用新版，当前程序只识别旧版课程 Tab，可能把新版登录成功判成失败，或无法读取课程。新版形考任务仍跳转旧站，扫码后的答题页面未变化，因此本次兼容范围集中在登录收尾、课程扫描和形考入口。

## 3. 用户与使用场景

面向已有桌面程序用户及同一工作台中的多个学生账号。用户从现有登录／刷新课程入口启动，程序按真实落地页面自动选择入口，不增加手动版本开关，不建立账号版本白名单。用户可沿用既有答题模式、提取模式、全部课程和可选课程范围。

## 4. 产品目标

- 新版账号能登录、列出全部课程、进入对应课程形考作业并到达扫码等待。
- 旧版账号的 Tab 课程、独立置顶形势与政策课程及原有检测保持可用。
- 异步切课和账号并发不造成错课、串号、漏课或残缺课表冒充成功。
- Codex 完成内部 E2E 和三组账号的扫码前真机验收；全部必要验证通过后升版至 2.4，提交并推送源码。

## 5. 非目标与明确不做

不新增 UI 壳、不重做程序工作台或学校页面；不重写 IAM／学校认证协议、不伪造 token；不修改扫码后的答题、AI、保存、提交、批阅和题库回写逻辑。不合并 T002／T003 的未收口题型问题。不要求用户扫码，不把扫码后真实答题闭环、全仓无关功能回归、人为断网或关机加入本次必过范围。不执行 GitHub Release、Tag、OTA、安装包上传；本次不默认打包。

## 6. 当前项目事实

本节为首次PRD确认时快照，当前实现和验证进度由执行文档维护。

- 旧版入口为 `learning.shou.org.cn/scenter`，登录收尾与扫描依赖 `#tab-courseList`。`electron/login.ts` 负责登录，`electron/detect.ts` 负责课程及作业检测。
- 新版首页为 `aiedu.shou.org.cn/`，主导航学习按钮进入 `/learning`。左侧课程卡切换中栏任务，准确的形考“去完成”打开 popup 到 `l.shou.org.cn/study/HomeWorkNew.aspx`。
- 新版当前页面样本有 8 门课程，含形势与政策，视口外卡片也在 DOM；这不是其它账号的固定数量或分页结论。
- 右栏暂无作业与真实形考列表可能不一致，不能替代旧站列表判定。
- 既有课程结果为 `{name, href, key}`；身份规则支持旧站课程参数名大小写。runner 在课程列表取得后并行调用 detectCourse，新版共享中栏采集必须避免并发争抢。
- 页面契约已取证，兼容源码尚未实现；IAM 完整重定向尚未由本任务真机验证。环境准备问题记录于避坑文档，不视为产品功能失败。

## 7. 用户流程

旧版：现有登录／刷新课程 → IAM 或复用会话 → 我的课程 Tab 与独立置顶课 → 课程目录 → 形考列表 → 作业预览与状态判定 → 合法可作答样本进入扫码等待。

新版：现有登录／刷新课程 → IAM 或复用会话 → 新版首页点学习（已在学习页则直接等待就绪）→ 左侧按序逐门切课 → 中栏准确形考“去完成” → popup 旧站形考列表 → 既有作业预览与状态判定 → 合法可作答样本进入扫码等待。

新版验收在真实入口显示二维码／等待扫码后停止。旧版按2026-10-12用户确认，只要求完整扫描、选课等待和正常停止，确认旧流程未受影响；不要求满分账号重新进入二维码。两版均不实际扫码，不点击验证完毕放行，不进入扫码后的答题、保存、提交或批阅。

## 8. 功能需求

### REQ-001 自动识别两版及登录就绪

触发条件：用户登录或刷新课程，或复用已有会话。
前置条件：沿用现有 IAM、旧版门户网关、会话复用与验证门禁。
用户操作：使用现有产品入口，不选择网站版本。
系统行为：按真实主机、路径与页面结构识别旧版或新版。新版首页点击主导航学习；已在 `/learning` 时等待课程区域。区分加载中、正常无课程、读取失败和就绪，不能因缺少旧 Tab 判新版登录失败，不能把页面壳当成课程就绪。真实重定向链需验证后确定，不凭截图替换全局登录入口。
数据变化：版本识别仅用于本次会话路由，不保存账号与版本固定映射。
状态变化：登录中 → 入口识别／课程加载 → 就绪或明确失败。
正常结果：两版均能进入各自课程扫描。
异常处理：未知落地页面、加载失败或认证失败给出脱敏原因，沿用账号失败隔离。
禁止行为：重写认证协议、伪造 token、强拼页面链接制造预期版本、未就绪提前报成功。
对应 AC：AC-001。

### REQ-002 保留旧版课程扫描

触发条件：识别到旧版学习中心。
前置条件：旧版课程区域已就绪。
用户操作：沿用现有课程范围设置。
系统行为：保留 Tab 内课程与独立置顶形势与政策课程的合并、既有顺序和身份去重，收藏课程不纳入扫描；保持原有课程目录到形考入口。
数据变化：按原有课程结果结构返回，重复身份去重，同名不同身份保留。
状态变化：扫描中 → 完整课程列表 → 既有作业检测。
正常结果：原有旧版账号与置顶课继续可用。
异常处理：加载／读取失败如实报告，不伪装成无课程或完整扫描。
禁止行为：删除旧版分支、只扫描 Tab 遗漏置顶课、按课程名合并不同课程。
对应 AC：AC-002。

### REQ-003 新版完整逐课采集

触发条件：新版学习页课程区域就绪。
前置条件：左侧课程列表可读，中栏用于当前选中课程；第三方嵌入入口须有明确可验证结构。
用户操作：沿用现有课程范围；不逐门手动切课。
系统行为：按左侧实际顺序读取课程名和卡片，不只读取视口可见项、不写死课程数量。逐门切课及采集入口，等待加载文案消失、选中态和对应课程任务容器匹配，避免上一门残留及并发争抢。遇到分页／虚拟列表须按真实形态取得完整列表。在进行中缺少形考任务时核对已完成／已逾期筛选；筛选只改展示，允许空态没有内部 role=list。不要自行启用只显示必做过滤。
数据变化：新版 ref 仅定位卡片；原平台采集完成才形成可供既有检测使用的课程结果。同类明确第三方入口仍保留课程行，以独立身份与暂不支持原因记录，不伪造旧站课程ID或形考链接。
状态变化：读取卡片 → 切课加载 → 对应课程就绪 → 获取入口；正常空态单独识别。
正常结果：所有实际课程均被核对，不漏视口外课程和形势与政策。
异常处理：普通课程切课失败、缺形考入口、身份不匹配或读取错误给出明确脱敏原因，不能把半份课表当成功。按CHG-001，当前课程明确进入非原平台的嵌入答题页面时，显示“新答题界面暂时不支持，等后续开发”，确认嵌入属于本次切课后直接跳过本课并继续其它课程，无需等待第三方加载或认证成功；上一课残留内容不能用于跳过本课，不能把普通缺入口或错误壳当第三方正常跳过。
禁止行为：共享中栏并发切课、用上一课任务、用百分比／右栏进度跳过课程、把筛选空态当加载失败。
对应 AC：AC-003。

### REQ-004 精确形考跳转及课程身份

触发条件：原平台当前课程任务容器出现形考入口；已确认第三方暂不支持课程不进入本形考入口流程。
前置条件：当前卡片和任务容器身份一致。
用户操作：由程序点击准确的形考去完成。
系统行为：限定课程中栏点击 `button[aria-label="去完成：完成课程形考作业"]`，接住 popup，等待旧站 `HomeWorkNew.aspx`，核对主机、路径及课程参数，并与当前课程的真实目录链接核对身份。实际旧站链接／跳转结果提供 `courseOpenId` 和 `minorCourseOpenId`，参数名匹配兼容大小写，保留原 URL；沿用既有课程 key 规则及返回结构，下游检测可沿用现有调度。
数据变化：从真实旧站入口取得 href／key；新版 `data-learning-course-ref` 不作为旧站 ID。
状态变化：当前课程就绪 → 跳转处理中 → popup 就绪 → 身份核对通过或失败。
正常结果：当前课程进入现有形考列表，无错课链接。
异常处理：popup 未打开、跳错主机／路径、课程参数不匹配明确失败并清理本次临时标签。
禁止行为：按按钮位置或短文案点其它去完成、点击我已完成／我已知晓、猜旧站 ID、只检查原页 URL。
对应 AC：AC-004。

### REQ-005 复用形考检测与扫码门禁

触发条件：任一学习中心进入旧站形考列表。
前置条件：已有课程身份、课程范围和工作模式设置。
用户操作：使用既有答题或提取模式检测入口。
系统行为：复用形考列表、网上记分作业与阶段性测验判定、作业预览和历史状态读取。保留满分跳过、日期窗口、次数上限、扫码闸门及其它现有规则。两版课程均支持答题及提取模式的检测；本任务验收不写真实题库。新版合法可作答样本由真实产品入口显示二维码／等待扫码后停止；旧版真实验收到完整扫描和选课等待，内部仍验证旧版扫码门禁。已有会话已验证时以隔离的未授权测试会话验证新版门禁。
数据变化：沿用既有课程／作业展示结果，不因本次验收改变学校完成状态、提交作业或写真实题库。
状态变化：作业检测 → 预览／状态判定 → 跳过、失败或扫码等待；验收到此停止。
正常结果：两版共享现有形考页面和扫码前流程，无需用户扫码。
异常处理：站点前置提示／无合法可作答样本如实报告并检查其它课程作业，受限项不伪造通过。
禁止行为：伪造二维码或扫码成功、点击验证完毕放行、为了本次兼容新增平行答题实现。
对应 AC：AC-005。

### REQ-006 账号隔离、错误与资源释放

触发条件：新旧账号混合运行、入口异常、停止或测试结束。
前置条件：沿用现有账号浏览器池与调度。
用户操作：使用现有停止操作，查看课程、作业和运行状态。
系统行为：每个账号独立课程、会话与状态，保持失败隔离和名额释放。明确区分无课程、无任务、加载失败、缺入口、错课及跳转失败，错误原因脱敏；正常关闭并释放程序创建的临时标签，不误关其它账号或用户标签。
数据变化：仅更新对应账号的运行结果，敏感凭据及会话数据不进入文档、日志、证据或源码提交。
状态变化：运行／等待 → 停止或失败 → 本账号资源释放。
正常结果：混合运行不串号，失败与停止均不泄漏浏览器名额。
异常处理：资源未释放或结果串号视为验收失败，修复后复测。
禁止行为：跨账号覆盖、残缺结果冒充成功、输出账号密码／Cookie／token／二维码图片／敏感完整 URL。
对应 AC：AC-006。

### REQ-007 Codex 内部 E2E 与真实扫码前验收

触发条件：兼容实现准备验收。
前置条件：环境完整性已核对，相关回归可运行；凭据仅运行时使用。
用户操作：无需扫码或再次指定验收负责人，验收由 Codex 执行。
系统行为：执行相关 TDD 回归、P0、类型检查和构建，有适用的现成格式／lint／安全检查则执行。内部脱敏夹具覆盖两版识别、首页／学习页、异步切课、视口外课程、重复身份、同名不同身份、置顶课、状态筛选空态、精确按钮、popup、错课链接和失败清理。三组账号从真实产品登录／刷新按钮验证课程扫描、形考和预览；NEW-01还须进入真实二维码等待，OLD-01/OLD-02完整扫描及选课等待即可。真实 Patchright 无头及可视化两种模式均验证，最后通过产品按钮停止释放。Chrome 取证仅辅助，直接 IPC 不替代需验收的产品按钮。
数据变化：结果在独立测试／真机文档中脱敏记录；夹具证据与真实站点证据区分。
状态变化：待验收 → 验证通过、失败待修复或样本受限。
正常结果：内部检查和三组账号扫码前真机验收均有真实证据，停止与资源释放正常。
异常处理：失败先定位修复复测；无合法样本如实记录受限，不提前升版。凭据行尾反斜杠按既有 Markdown 续行清理规则处理，不打印清理前后值。
禁止行为：本地模拟冒充真实登录、P0 冒充真实 E2E、要求用户扫码、声称未执行的 Windows 真机通过。
对应 AC：AC-007。

## 9. 数据、状态与业务规则

- 课程结构沿用 `{name, href, key}`，当前身份为旧站 `courseOpenId` 与 `minorCourseOpenId` 组合；已有无 ID 情况的 href 身份回退沿用既有规则，不用课程名猜身份。同名不同身份独立保留，重复身份只计一次。
- 新版卡片 ref 是运行时不透明定位值，不固化进选择器或源码。旧站参数兼容 `courseOpenId`／`courseopenid`、`minorCourseOpenId`／`minorcourseopenid`，保留真实 URL。
- 页面就绪须同时满足当前课程匹配和加载完成；有任务与空态均可就绪。任务筛选 active／completed／overdue 只改变展示。
- 右栏记分作业、左栏学习百分比与右栏学习进度不是作业完成依据；真实形考列表及既有状态规则为准。
- 每个账号独立扫描和展示；同账号共享中栏切课采集串行。采集完成后的独立旧站检测可沿用现有并行策略。

## 10. 页面与 UI 需求

沿用现有桌面入口、课程及作业行、运行状态和扫码等待界面，新增路径接入现有状态展示。学校两版契约同时保留，选择器集中沿用现有真源。

| 新版对象 | 已取证定位 | 必要规则 |
| --- | --- | --- |
| 学习导航 | `nav[aria-label="主导航"] button[aria-label="学习"]` | 排除同名移动端按钮 |
| 左侧课程卡 | `article[data-learning-course-card]`、同卡 h3、`button[aria-label^="切换课程："]` | 按实际顺序读完整列表；active 属性核对选中 |
| 选中态 | `data-learning-course-card-active="true"` | 防止错课 |
| 中栏 | `[aria-label="课程学习空间"]`、`[role="region"][aria-label="课程任务"]` | 加载时旧任务移除，等当前课程就绪 |
| 课程外层容器 | `div[aria-label="课程名 课程任务"]` | 无 role，空态仍存在；同名内部 role=list 只非空存在 |
| 状态筛选 | `button[data-figma-segmented-tab-key]`、`aria-pressed` | key 各为 active／completed／overdue；不能用 AX checkbox 角色定位 |
| 形考跳转 | `button[aria-label="去完成：完成课程形考作业"]` | 与在线学习、成绩查询、完成确认按钮区分；接住 popup |

不固化账号动态任务 ID 或 course-ref，不按短视觉文案、按钮位置及当前样本数量实现。

## 11. 异常、边界与安全规则

缺入口、失败、无课程和正常空态须能区分。分页／虚拟列表、筛选后的真实任务入口、IAM 完整重定向依据实测确定，不当成已验证。没有合法可作答样本时检查其它课程及站点提示，记录真实受限项；不能伪造二维码、越过验证门禁或提前升版。

验收不提交作业、不点击我已完成／我已知晓、不写真实题库。凭据、Cookie、token、二维码图片及敏感完整 URL 不进入文档、截图证据文件、日志或提交。凭据仅从用户已提供消息运行时读取，行尾 Markdown 续行标记不得误当密码字符。

保留用户改动；本会话未授权删除文件，尤其不得删除项目外文件。环境恢复先核对来源和可用完整副本，不覆盖用户变化，不擅自删除 Git 对象或重写历史。

## 12. 兼容性与限制

保留 IAM、旧版门户网关、两工作模式、课程范围、日期窗口、满分跳过、次数上限、扫码闸门、失败隔离、停止和浏览器名额释放规则。两版仅入口不同，旧站形考检测共用。

本次真机为当前 macOS，覆盖真实 headless 与 headed；headless 扫码等待不强制切为 headed。Windows 真机不在本次已确认范围，不声称通过；若另需程序交付仍按项目规则双平台构建。
