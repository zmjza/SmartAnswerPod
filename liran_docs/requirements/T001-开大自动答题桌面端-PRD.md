### 0.1 当前浏览器模式基线（2026-09-21）

本节是当前有效规则，并覆盖本文后续历史版本、用户原话归档和旧验收描述中的“隐藏式无头、同一进程 show/hide、打开可视化浏览器、验证后再藏回去、不 relaunch”等旧规则：

- 无头模式必须以 Playwright `launchPersistentContext(..., { headless: true, channel: 'chromium' })` 启动，后台静默运行且不创建可见浏览器窗口。
- 可视化模式必须以 `headless: false` 启动，显示真实浏览器窗口。
- 两种模式是独立启动模式，禁止通过 CDP 移窗、macOS 进程隐藏、最小化或同一上下文显隐来互相伪装。
- 任务运行中锁定浏览器模式；用户停止并释放该生浏览器后才可修改，下一次启动按新模式创建上下文。
- 重新启动继续使用该生原持久化 profile，保留登录态；禁止同一 profile 同时启动两个上下文。
- 无头模式遇到作业扫码时继续保持无窗口，通过桌面程序内的真实二维码截图完成扫码；不再临时转换为可视化模式。二维码入口文案为「查看作业二维码」，不再要求打开或隐藏浏览器窗口。

### 0.2 当前 UI 与验证入口覆盖

以下规则优先于本文后续历史轮次中的旧文案：

- 学生卡片的浏览器模式只表示下一次启动使用的真实 Playwright 模式：无头为 headless:true 且无窗口，可视化为 headless:false 且窗口可见。
- 运行中不切换模式，不通过窗口显隐模拟模式；停止并释放后才按新模式重新启动并复用学生 profile。
- 扫码、验证码和人脸验证统一使用程序内验证入口。当前按钮为「查看作业二维码」和「验证完毕」；不再使用「打开可视化浏览器」作为当前功能入口。
- 无头扫码不会显示浏览器窗口；可视化模式保持浏览器窗口可见。验证成功只恢复队列，不改变浏览器模式。
- PRD 1.16 的 CHG-026 UI 增量优先于历史页面布局描述：学生列表按账号并行数量逐行显示，设置页固定内置 Supabase URL/Publishable Key，仅让用户填写硅基流动 API Key；提取题库模式隐藏作业重新答题次数。
- 本轮课程分页和复制粘贴批量导入由 Codex 使用模拟数据 E2E 验证，其余 UI 由用户验收；不改变业务状态机和浏览器池。

## 1. 产品/功能概述

本产品是上海开放大学管理员自用、也可给朋友安装使用的桌面自动答题器。它不是浏览器插件本体。用户在 App 里维护学生账号，程序用 Playwright 登录开大学习平台，只扫描门户「我的课程」，进入每门课的「形考作业」，只处理「网上记分作业列表」和「阶段性测验」中「客观题且权重大于 0%」的作业。作答策略是自己题库优先，未命中再用硅基流动多模型降级答题，答完由程序走页面两次确认提交。提交并已批阅后校对：AI 答对的题写入云端题库，题库答错的题从题库删除。最终目标是尽量全靠自己题库把客观形考做到 100 分。

形考作业按每个学生账号自己的课表走：登录的是哪个学生，就只做该生「我的课程」里的形考两块，不是全站公共卷，也不是操作员自己的课。每个学生独占一个 Playwright 浏览器；扫码或验证暂停时这个浏览器名额继续占着，不能把名额让给另一个学生补位。

技术形态：Electron 桌面应用，macOS 与 Windows 双端；技术栈为 Electron + Vite + TypeScript + Vue3；Playwright 在主进程运行并捆绑 Chromium；OTA 使用 electron-updater + 当前 GitHub 仓库的 GitHub Releases。题库使用一份云端 Supabase 表，全账号共用。密钥和账密只在设置页填写，用系统加密存在本机。

## 2. 背景与问题

开大形考客观题分布在多门课的网上记分作业和阶段性测验里。人工逐号登录、进课、判定要不要做、扫码、逐题点选、提交、再把对过的题攒成题库，重复劳动大。用户已有「自动上号器」Chrome 扩展，能填账密登录，但不能完成检测、作答、提交、题库闭环。站点作答页没有原生 radio/checkbox，提交不是浏览器原生 confirm，第一次点「做作业」可能弹出微信扫码，同一学生号多份作业并行时如果各开隔离浏览器会重复弹码。需要一个桌面端把登录、检测、闸门、作答、提交、校对、题库维护做成可看进度的闭环。

## 3. 用户与使用场景

主用户是网站管理员本人，次要用户是朋友。每人在自己的安装里填写学生账密、硅基流动 API Key、Supabase 地址和 anon key。安装包不含密钥。

典型场景：

> PRD 1.15 当前规则：下方历史场景中“打开可视化浏览器扫码”已由 REQ-026 覆盖。无头浏览器保持隐藏，用户在桌面程序中查看、复制或刷新作业二维码；扫码后仍须点击“验证完毕”，主进程复核成功才继续。

- 导入或录入多个学生账号，点「登录并刷新课程」，看每门课客观题检测结果。
- 检测完成后自动开答。进度里能看到当前在点哪一步，以及本题是题库答题还是 AI 答题。
- 第一次点「做作业」弹微信扫码时，该号暂停并继续占用名额。无头模式在 App 内查看、复制或刷新二维码；可视化模式也可直接扫浏览器中的二维码。扫码后由用户点击「验证完毕」，主进程复核成功才继续。
- 默认无头。学生卡片可在任务空闲时选择无头或可视化；运行中锁定，停止并释放后再修改，下一次启动按新模式运行。
- 答完自动提交。未满分按次数规则连刷；AI 对的入库，题库错的删除。
- 独立「提取题库」模式：只抽已批阅卷，不答题不提交。
- 设置页改 Key、并行度、无头/显示、日志。

## 4. 产品目标

- 第一期只自动完成「网上记分作业 + 阶段性测验」里客观题且权重大于 0% 的作业。
- 题库优先、AI 兜底，界面必须显示「题库答题 / AI 答题」。
- 已批阅 100 分的作业跳过。
- 不续做，一律点「做作业」新开。
- 程序自己提交，用户不用在 App 里再点一次交卷。
- 同一学生号扫码只做一次，约 2 小时内以页面是否弹码为准免扫。
- 题库云端一份，题干加选项集合去重，答案按选项正文回填，顺序打乱仍命中。
- 有限连刷加自动提取，让题库越积越全，后续运行再凑 100 分。

- 第一期不做浏览器扩展主程序，不把自动上号器整份拷进仓库，不把扩展嵌进 Electron。
- 不扫「收藏课程」。
- 不点「视障学生做作业」，不打开 `/study/assignment/readpreview.aspx`。
- 不点作答历史里的「续做」，不打开 `/study/assignment/continuation.aspx` 当主路径。
- 第一期不点课程实践、书面作业、论文、资源学习、直播出勤、面授出勤。
- 客观题权重 0% 不做。非客观题、未知题型行第一期只标记跳过。
- 不以 A/B/C/D 或 `data-index` 作为题库身份或标准答案。
- 不直接 POST 提交接口绕过页面 `xcConfirm`。
- 不绕过 `doHomework` 直接 `goto` 作答页，不用程序自己的 2 小时计时跳过扫码。
- 不给同一学生号的每份作业各开隔离浏览器。
- 第一期不按 CPU 自动限流，不内嵌完整浏览器，不导出题库。
- 禁止全员共用一个浏览器，禁止一份作业开一个浏览器，禁止扫码暂停时关掉该生浏览器给排队学生补位。
- 无头必须使用 Playwright 真实 headless:true，可视化必须使用真实 headless:false。禁止在扫码时切换启动模式，禁止用 CDP、macOS 隐藏、最小化、负坐标或同一上下文显隐伪装另一模式。禁止把无头/可视化切换按钮放进顶栏 CPU 那一行；运行中锁定，停止释放后才能按新模式重新启动并复用 profile。
- 不把学号、token、JWT、账密、硅基流动 Key、Supabase Key、service role 写入仓库、安装包、文档或题库内容。
- 参考图里的样本姓名学号不入库。
- 毕业设计、社会实践导航第一期不用。
- UI 像素级精细视觉不在本 PRD 锁死，留给 UI 目标；本文件只锁信息架构和「比参考图更精致」的方向。

## 7. 用户流程

设置：账密或 Excel、硅基流动 Key、Supabase URL、Supabase anon key、账号并行默认 2、课程并行默认 2、浏览器显示默认关、日志默认开。

浏览器名额：账号并行 N 表示同时最多 N 个学生浏览器。取得名额才启动该生那一个持久化浏览器。扫码暂停、等批阅都不释放名额。只有该生本轮结束、用户停止或删除、不可恢复失败、浏览器进程死掉才释放。释放后排队学生才能补进。已占名额的其它学生继续跑，排队的继续等。

进度：以上每一步网页点击、跳转、弹窗都按 REQ-022 推一条进度。主界面订阅五层状态机，学生卡片显示当前动作，必须能看出登录、课程 x/N、哪份作业第几题、题库还是 AI。

检测（主按钮「登录并刷新课程」只做这一段）：

1. 每账号走 IAM `iam.shou.org.cn` 填学号或账号和密码并提交，进入 `learning.shou.org.cn/scenter`；若停在 `/login` 再跳 scenter。
2. 账密错误停该号，其它号继续。中途会话过期该号重走 IAM，连续失败停该号。IAM 验证码、微信扫码、行业分校人脸失败落到与作业扫码同一套暂停 UI。
3. 确认 `#tab-courseList.is-active`，否则先点它。只取 `#pane-courseList .course-item`，忽略收藏课 `#tab-collections` / `#pane-collections`。
4. 按 DOM 顺序进课，先点 `#courseHomeWorkNew`「形考作业」。
5. 只读 `#onlineHomework` 与 `#phasedTest`。检测阶段不点「做作业」。一门课两块扫完再下一门。
6. 要做的行点「查看」进预览，判断满分、窗口、次数。提取模式下检测后只抽已批阅，不开答。

答题（检测完成后自动开始，答题模式默认含自动提取）：

1. 按该份可答次数决定当次最多提交几轮。
2. 点「做作业」新开，不点续做、不点视障。
3. 同一号未验证时同时只允许一份点「做作业」。弹「微信扫码验证」则该号暂停并占位。无头模式保持真实 headless:true 且没有浏览器窗口，只通过程序内二维码查看、复制或刷新；可视化模式保持真实 headless:false 且窗口全程可见，也可使用程序内二维码。点击「验证完毕」后先由主进程复核成功态，再刷新其余预览并点「做作业」，不改变浏览器模式。
4. 进入 `assignment/preview.aspx`，从第一题到最后一题：题库 hash 命中则按选项正文点选；未命中走硅基流动按序降级；未知题型或全部模型失败则该题空着继续。
5. 程序点 `#submitHomeWork`，过两次 `xcConfirm`（深蓝确定）。成功只认预览页作答历史出现提交时间更新的新记录。
6. 已批阅后点历史「查看」进入 `history.aspx` 校对：AI 答对入库，题库答错删除。批阅超时记待回写，下次该号检测或答题时先补抽补删。
7. 到 100 立刻停；未满分且未打满当次上限、且本轮已批阅并校对完成，才再新开。批阅超时或查看失败则这份记待回写并停止连刷，不得未校对就再新开。打满当次上限仍不是 100 则离开，下次再做。

## 8. 功能需求

### REQ-001 产品形态、平台与技术栈

触发条件：实现或安装本产品。
前置条件：目标机器为 macOS 或 Windows；本任务为新项目空仓库。
用户操作：用户安装桌面 App 并启动。
系统行为：产品是 Electron 桌面应用，不是浏览器插件本体。平台同时支持 mac 与 Windows。技术栈固定为 Electron + Vite + TypeScript + Vue3。Playwright 只在 Electron 主进程跑，安装包捆绑 Chromium，不依赖用户本机 Chrome。登录能力从本机自动上号器扩展搬改 content.js 的填账密和点登录，以及 iam.shou.org.cn 到 learning.shou.org.cn/scenter 这条链；不要把扩展整份拷进仓库，不要当 Chrome 扩展嵌进 Electron。扩展已覆盖 iam.shou.org.cn、learning.shou.org.cn、l.shou.org.cn；毕业设计和社会实践导航第一期不用。
数据变化：无业务表变化；本机生成 Electron 用户数据目录，不进 git。
状态变化：应用可启动，主界面可见。
正常结果：mac 与 Windows 都能运行同一套业务；无头自动化使用捆绑 Chromium。
异常处理：本机缺少自动上号器源码时，登录模块开发前必须读取该本机路径；缺失则标记受阻，不得编造选择器。
禁止行为：禁止把插件当主程序发布；禁止依赖用户已装 Chrome；禁止把扩展目录提交进本仓库。
对应 AC：AC-001

### REQ-002 密钥、账密与本机加密

触发条件：用户打开设置页填写凭据，或程序读取凭据去登录、调 AI、访问题库。
前置条件：操作系统提供安全存储能力。
用户操作：在设置页填写或更换学生账密、硅基流动 API Key、Supabase project URL、Supabase anon key。
系统行为：上述凭据一律用系统 safeStorage 加密存在本机。设置页支持更换硅基流动 API Key。朋友各自在自己的安装里填同一套 Supabase URL 与 anon key。禁止 service role 进入客户端代码、git、安装包。anon key 泄露等于题库可被读写，第一期接受，因为使用对象是自己和朋友。
数据变化：本机加密存储更新；题库与 git 不出现明文密钥。
状态变化：凭据从「未配置」变为「已配置」或「已更新」。
正常结果：重启 App 后仍能读出凭据并使用；仓库和安装包搜不到真实密钥。
异常处理：加密存储不可用时拒绝保存明文到普通配置文件，并在设置页提示无法安全保存。
禁止行为：禁止把账密、硅基流动 Key、Supabase Key、token、学号样本写入仓库、文档、安装包或日志全文；禁止把 service role 写死进客户端。
对应 AC：AC-002

### REQ-003 主界面信息架构、实时进度与本机状态

触发条件：用户打开主界面，或自动化每完成一次网页点击、每答一题。
前置条件：App 已启动。
用户操作：查看顶栏、课程列表、学生卡片、底栏进度；悬停课程行看明细；在学生卡片右上角切换无头浏览器或可视化浏览器。

### REQ-005 并发模型与 Playwright 上下文

触发条件：用户启动检测或答题，或调整并行度。
前置条件：至少有一个已配置账号；Playwright Chromium 已捆绑。
用户操作：使用默认并行或改成单账号单课。
系统行为：多并发是多个学生账号一起跑，每个账号内部多门课一起跑，即账号级并行乘以课程级并行。也必须能切成单账号单课。顶栏浏览器数计已占用的学生浏览器（含暂停占位）。同一个学生账号必须共用一个 Playwright 浏览器和一份用户目录（同 cookie、同 localStorage），让扫码后约 2 小时免扫在 App 重启后仍有效。不同学生用不同浏览器。禁止给同一号的每份作业各开隔离浏览器。窗口默认隐藏（隐藏式无头）。弹码时不自动显示；用户点「打开可视化浏览器」才显示该生窗口；点「验证完毕」后立刻自动再藏。可视化模式该生窗口全程可见，弹码不必再点打开，验证完毕不藏；切回无头立刻藏。切换只改显隐，不用 headless:true 切换 headed。用户目录不进 git、不进安装包、不进题库。崩溃或中断后再跑：不续做，检测后该新开就新开。
每个学生账号独占一个 Playwright 浏览器进程，也就是一份 launchPersistentContext 加一份 userDataDir。该生所有课、预览、作答、历史都是这个浏览器里的标签，不是新浏览器。全员不得共用一个浏览器。账号并行 N 是同时允许占用的学生浏览器数；占用规则、暂停占位、禁止补位见 REQ-021。默认不使用 headless:true 再切换 headed，见 REQ-021。
数据变化：本机用户目录写入 cookie 与 localStorage；不进仓库。
状态变化：学生从排队中到占用中；无头扫码暂停时窗口仍隐藏，用户点开后才可见，点验证完毕后立刻再隐藏；可视化模式窗口一直可见，验证完毕不藏；进程不关。
正常结果：两账号可同时跑则占两个浏览器；同一号多课共享同一个浏览器会话；重启后仍可能免扫（以页面为准）。
异常处理：并行度超出机器压力时只在顶栏告警，第一期不自动限流。某号浏览器进程崩溃则停该号、释放该名额，已占用的其它号继续，排队号这时才可以补进。
禁止行为：禁止一号多份作业各开隔离浏览器；禁止依赖用户本机 Chrome；禁止把用户目录提交进 git；禁止暂停时把该生浏览器关掉给别人用。
对应 AC：AC-005、AC-021

### REQ-007 检测范围与形考列表判定

触发条件：该号已进入学习门户，开始刷新课程。
前置条件：`#pane-courseList` 可见。
用户操作：无额外操作，程序自动扫课。
系统行为：只扫门户「我的课程」，按 `#pane-courseList .course-item` 的 DOM 顺序。课程名取 `.course-title a.el-link .el-link__inner` 文本。忽略收藏课程。进课先点 `#courseHomeWorkNew`「形考作业」。只处理两块：网上记分作业列表 `#onlineHomework`、阶段性测验 `#phasedTest`。选择器必须限定在这两块，同页课程实践等面板即使有「查看」也不点。无作业判定：对应块标题包含「：暂无数据」（例如「网上记分作业列表：暂无数据」「阶段性测验：暂无数据」）。两块都暂无数据则该课标记无作业。有表格时扫 `#onlineHomework tbody tr` 与 `#phasedTest tbody tr`。题目类型取第 4 个 td 是否包含「客观题」；权重取权重列，解析百分数。客观题且权重大于 0%：要做，点该行「查看」进预览。客观题且权重等于 0%：标记不需要做，不点查看或点了也不开答。非客观题、未知题型行、课程实践、资源学习、视障：第一期跳过并标记。不要用课程徽标判断要不要做作业。
范围按学生账号隔离：登录的是学生 A，就只做 A 自己门户里的形考作业，不拿学生 B 的课表，也不是操作员本人的课，更不是全站一份公共作业池。每个学生各自检测、各自答题、各自提交。
数据变化：该号课程与作业检测结果写入本机运行状态。
状态变化：课程行变为无作业、已检测、权重0跳过、非客观题跳过或待答题。
正常结果：能列出我的课程门数与名称；收藏课不出现；该做的客观题被列入。
异常处理：形考页结构对不上时该课标记检测失败，其它课继续；不得猜课程实践里的查看按钮。权重或题目类型解析失败的行跳过并标记，不得当要做。
禁止行为：禁止扫描收藏课；禁止第一期做主观题、实践、资源学习；禁止把权重 0% 客观题当要做。
对应 AC：AC-007

### REQ-008 预览页满分、续做、窗口与次数判定

触发条件：检测阶段对要做的行打开 `assignment-preview.aspx`。
前置条件：该行已判定为客观题且权重大于 0%。
用户操作：无。检测阶段只读预览，不点「做作业」。
系统行为：作答历史已批阅且分数为 100：整份跳过，不再做、不再提交。已批阅但小于 100，或未完成提交、未提交记录、有「续做」：不点续做，列入要做，以后点「做作业」新开。当前时间早于形考开始或晚于形考结束：窗口外跳过，不要硬点。答题前必须先判定可答次数。来源：列表「作答次数」可见文案（如 `1/无限制`、`2/3`）和 hidden `input[name=replyCount]`。文案含「无限制」或 replyCount=-1 视为无限制。有上限时剩余等于上限减已用；解析不到已用则剩余按上限算。剩余小于等于 0：次数用尽，跳过。只读 Playwright 有时读丢 replyCount，以页面真实 DOM 或 CDP 为准。
数据变化：该份作业记录满分跳过、窗口外、次数用尽或列入要做。
状态变化：对应课程行或明细更新。
正常结果：100 分作业不会进入答题队列；有续做也不点续做。
异常处理：历史表解析失败时不得当成 100 分跳过，应记信息不全并列入人工可看的异常，不编造分数。
禁止行为：禁止点续做；禁止窗口外硬点；禁止未判定次数就连刷。
对应 AC：AC-008

### REQ-009 检测与答题两段工作流

触发条件：用户点击「登录并刷新课程」。
前置条件：至少一号账密可用，模式为答题或提取题库。
用户操作：只点一次主按钮。
系统行为：主按钮只做检测，不在检测阶段点「做作业」。检测完成后，答题模式自动开答，不再让用户点第二次。提取题库模式只抽已批阅，不开答、不提交。检测顺序：每账号登录门户，只扫我的课程，按 DOM 顺序进课，点形考作业，只读两块列表，要做的行进预览判断满分窗口次数。一门课两块扫完再下一门；多账号、每账号多课按设置并行。答题阶段按 REQ-015 决定当次轮数，按 REQ-010 过扫码闸门，按 REQ-011 到 REQ-014 作答提交，按 REQ-016 校对。其它课和其它号仍并行。一个账号卡在扫码时其它账号继续。
数据变化：检测结果落本机运行状态；答题结果随后更新。
状态变化：从检测中到已检测，再到待答题或自动开答。
正常结果：点一次主按钮即可完成检测并在答题模式下自动开答；进度能区分两段。
异常处理：检测失败的课不进入开答；已检测成功的课仍可开答。
禁止行为：禁止检测阶段点「做作业」；禁止提取模式误开答。
对应 AC：AC-009

系统行为：每次提交成功后必须在当前运行内等待本次记录已批阅，打开本次历史「查看」，完成逐题校对、AI 正确题去重入库、题库错题删除及回读确认，才算该轮完成。无论得分是否满分，都不能跳过历史校对。未满分且仍在本轮次数上限内，只能在回写成功后再新开；达到上限则回写成功后进入下一作业或课程。批阅未出、历史读取失败、题目匹配失败、Supabase 写入失败或删除回读失败时，保存恢复证据，同时保持该学生浏览器和名额占用，在当前运行原地重试，不释放浏览器、不进入下一轮、下一作业或下一课程。云端两个已验证答案冲突时保留旧值并标记 conflict=true，该冲突已完成写回处理，不得误当成无限待回写。只有用户主动停止、程序崩溃或系统退出才允许留下恢复队列；下次启动先恢复，但正常运行不得以“下次补偿”为收口。
数据变化：本机待回写队列新增或完成后移除；补做成功则更新题库。
状态变化：课程或作业显示等待批阅、校对中或本轮回写重试；回写完成后清除。重试期间学生 slot 保持 occupied。
正常结果：批阅晚到的卷不会丢掉入库和删错。
异常处理：历史记录暂不可读或仍未批阅时继续原地等待；用户停止或程序异常退出时保留恢复记录，不假装已入库。
禁止行为：禁止把待回写当提交失败；禁止正常运行中释放浏览器并把责任推到下次；禁止未回写完成就继续其它课程。
对应 AC：AC-017

### REQ-018 云端题库表、导入与两种提取模式

触发条件：用户导入 JSON，或选择提取题库模式，或答题后自动校对。
前置条件：Supabase URL 与 anon key 已配置。
用户操作：在设置或独立题库页导入 JSON；或把学生卡片模式设为提取题库。
系统行为：题库用 Supabase 云端一份，全账号共用，本机不作为主库。禁止一门课一张表。最小表 questions 字段：qtype（single/multiple/judge）、stem、options jsonb、answer_texts jsonb、content_hash unique、course_names text[]、source（import/extract/ai_verified）、verified、conflict、updated_at。身份与 upsert 规则同 REQ-012。course_names 不进 hash：提取或作答入库时写入当前门户课程标题（去首尾空白）；同一 hash 以后在其它课再出现则追加不重复课程名；JSON 导入没有课程名则保持空数组。该列只供以后按课浏览/检索，作答热路径只 `where content_hash = $1 limit 1`，超时 2 秒当未命中。不提供导出，云端就是备份。导入 JSON 每项含 qtype、stem、options 正文数组、answer_texts 正确选项正文数组，课程名可选。重复导入因 content_hash 唯一而合并，不新增重复行，有课程名则并入 course_names。提取分两种都必须有。独立模式：学生卡片选「提取题库」，登录该生，课程，形考两块，预览里所有已批阅「查看」，从 history.aspx 抽题干、选项、正确项 upsert，不点做作业、不提交。自动模式：答题模式下提交并已批阅后校对整份，规则同 REQ-016。学生卡片默认答题模式含自动提取。
数据变化：questions 表 upsert；独立提取不产生新交卷。
状态变化：导入成功显示合并条数；提取模式显示当前作业与本次运行的提取统计。每一份作业都必须单独记录并实时显示：新增题目数、去重题目数、跳过题目数、冲突题目数、写入失败数；账号和本次提取运行还必须显示所有作业合计的五项统计。统计只能来自真实历史提取与 Supabase 写入结果，不能使用演示固定值。
正常结果：重复题不新增行；独立提取不答题；每份作业明细合计与本次运行总计一致。
异常处理：JSON 缺字段跳过该条并计数；Supabase 写失败记待回写或导入失败，不卡死其它账号。
禁止行为：禁止导出题库文件；禁止 service role；禁止独立提取时点做作业。
对应 AC：AC-018

#### REQ-018A 独立提取题库模式完整闭环（确认版）

独立提取模式与自动答题模式完全分开。用户在学生卡片选择「提取题库」后运行，账号并行限制同时处理的学生数；每个学生扫描全部「我的课程」，默认检查网上记分作业和阶段性测验，但只处理客观题（单选、多选、判断），跳过主观题、实践、论文、资源学习及权重为 0% 的作业。提取模式不能因为成绩、作答次数或已完成状态跳过符合范围的作业。

提取模式不按分数过滤：100 分、非 100 分和低分作业都要检查。每门课程、每份作业都读取历史记录；只有状态为「已批阅」且存在可靠「查看」链接的记录才打开 history.aspx。未批阅、未提交记录、未完成提交、只有「续做」、没有可靠历史链接的记录都跳过并保留原因。提取模式禁止点击「做作业」、点击「续做」、自动答题、调用 AI、提交作业或修改学生作答记录。

并发规则：多个学生可同时提取；每个学生可以按课程并行限制同时处理多门课程；每门课程可以并发处理多个作业历史任务。一个学生始终只使用一个持久化 Playwright Context，同一学生的历史记录使用该 Context 下的多个 Page；禁止每份作业新开浏览器、同一学生创建多个持久化 Context 或跨学生复用 Page/Context。账号并发、课程并发和历史页面占用都必须进入实时状态和名额统计；提取中的学生、浏览器和页面任务结束前不能提前释放学生占位。

history.aspx 逐题读取题型、题干、全部选项、学生选择、标准答案、批阅结果、课程名、作业名和历史记录信息。只有明确判定正确且题型、题干、选项和答案正文完整可读的题目才进入题库去重；错误题、无法判断题、未知题型、空题干、空选项、替换字符或结构损坏题目跳过并记录原因，禁止入库。

每份作业实时记录新增、去重、跳过、冲突、写入失败五项统计；学生级和本次运行级也必须显示所有作业明细逐项合计。新增表示题库不存在且成功写入；去重表示已有答案一致并只合并课程名；冲突表示已有已验证答案不同，保留原答案并标记冲突；写入失败表示 Supabase 请求、权限、网络或回读确认失败，不能显示成功。总计只能由各作业真实结果汇总，不能重复累计、漏算或使用演示值。

主界面必须实时显示当前学生、课程、作业、历史记录、题号/总题数、账号并发、课程并发、历史页面数、当前作业五项统计、学生五项统计、本次运行五项总计、课程和作业完成进度，以及「登录中、扫描课程、检测作业、读取历史记录、提取正确题、去重写入、写入失败、提取完成」等具体动作，不能只显示「提取中」。单份作业失败时记录具体原因并继续其它作业和账号；已完成的写入结果不能丢失；失败项保留为待处理状态。学生只有在全部课程、全部符合范围的作业历史处理完成，正确题完成去重写入，失败项已记录、每份统计完整后才算提取完成；所有学生满足同样条件后本次运行才结束。

### REQ-021 Playwright 学生浏览器池、暂停占位与禁止补位

> 当前执行规则以 0.1 基线为准：无头和可视化分别启动，运行中模式固定；停止并释放后才可切换并复用同一学生 profile。下方旧 show/hide 说明仅保留需求演进记录，不再用于实现或验收。

触发条件：同时跑多个学生账号，或任一学生进入扫码、验证码、人脸等暂停。
前置条件：账号并行 N 已配置，默认 2；捆绑 Chromium 可用。
用户操作：启动检测或答题；在学生卡片右上角切换无头或可视化；无头扫码时点打开可视化浏览器和验证完毕；或停止、删除某号。
系统行为：每个学生账号独占一个 Playwright 浏览器，用 launchPersistentContext 指向该生自己的 userDataDir，一生一目录、一生一活上下文。该生所有课程和作业只在这个浏览器里开 Page，不新开浏览器。账号并行 N 是同时允许处于占用中的学生浏览器数。学生要先从名额池取得名额才启动浏览器；未取得则状态为排队中，没有浏览器进程。占用后直到释放前，名额一直算这个学生的。释放条件只有：该生本轮检测和答题或提取全部结束、用户点停止、用户删除（先停再删）、不可恢复登录失败并结束该生、该生浏览器进程死亡并停止该生。以下情况不释放：微信扫码暂停、IAM 验证码、人脸、等用户点验证完毕、等批阅、待回写补抽过程中、某一份作业做完但同号还有下一份、AI 请求中、提交中。暂停占位的含义：该生 Chromium 进程、Context、已打开页面全部保留，顶栏浏览器数不减，排队学生不得启动浏览器顶上来做作业。其它号继续仅指已经占到名额并且未结束的学生继续跑。Playwright 不能把已有 headless 浏览器原地改成 headed，因此禁止 headless:true 再切换或 relaunch headed。每生浏览器一开始就是真实窗口的持久化上下文。启动后若该生 display_mode 为 headless（默认）立刻隐藏，对用户就是隐藏式无头；若为 visual 则保持可见，不要先藏再亮。排队中切换只改 display_mode，启动时按当时模式显隐。弹码时只暂停并出按钮，禁止自动把窗口弹到前台。用户自己点「打开可视化浏览器」才显示并前置该生已有窗口，禁止为此新开第二个浏览器，禁止打开别人的窗口。用户点「验证完毕」后：无头模式立刻自动把窗口重新隐藏并继续跑；可视化模式保持可见。学生卡片右上角切换无头/可视化只改变该生已有窗口显隐，禁止 relaunch，禁止新开浏览器。进程不关。同一 userDataDir 同一时刻只允许一个活上下文；禁止两生共用目录，禁止同一生开两个持久化上下文。App 重启遇到目录锁时先处理锁或提示，不要硬开第二个。某生 Chromium 崩溃则只停该生并释放名额，这时排队学生才可以补进。课程并行限制的是该生浏览器内同时干活的标签数，不是再开浏览器。一份作业本轮结束后可关掉它的作答页以减少标签；暂停时不得回收该生页面给别人。停止或删除才是合法补位入口。
数据变化：本机记录名额占用表（学生标识、占用/排队、userDataDir、pid）；用户目录仍只属于该生。
状态变化：排队中到占用中到需验证占位再到占用中；或占用中到已释放。
正常结果：N=2 时最多两个学生浏览器；第三个学生排队；其中一人扫码时仍是两个浏览器，不会变成一人扫码、另一个新人顶上。
异常处理：目录锁冲突则该生失败并提示，不抢别人目录。窗口显示失败则保持占位并提示手动打开，不释放名额。崩溃释放名额后从排队头按账号列表顺序补进一个。
禁止行为：禁止全员一个浏览器；禁止一份作业一个浏览器；禁止暂停关浏览器补位；禁止 headless 与 headed 来回 relaunch 抢同一 userDataDir；禁止把 A 的 Page 或 Context 交给 B；禁止用 Electron BrowserWindow 当开大站点浏览器。
对应 AC：AC-021、AC-023

### REQ-022 颗粒进度状态机与主界面订阅

触发条件：App 启动后任意学生进入排队、启动浏览器、登录、检测、答题、扫码暂停、提交、校对，或用户打开主界面查看进度。
前置条件：主界面已按 REQ-003 布局；Playwright 在主进程；名额规则按 REQ-021。
用户操作：查看主界面实时进度。在学生卡片右上角切换无头或可视化。无头扫码或验证码时按卡片提示打开可视化浏览器并点验证完毕；可视化模式只需扫码后点验证完毕。用户不为状态机另点其它按钮。
系统行为：主进程维护一份五层状态机，渲染进程只订阅展示，不得另造互不相同的文案。状态码用稳定英文枚举，界面用中文。网页每发生一次点击、跳转、弹窗出现或消失，都必须向该号推一条进度事件，用户不看隐藏 Chromium 也能知道他在做什么。
第一层名额/浏览器 slot：queued 排队中（未占名额、无浏览器）；launching 启动浏览器（已占名额，正在 launchPersistentContext）；occupied 占用中（默认窗口隐藏）；occupying_verify 需验证占位（无头：窗口仍隐藏，等用户点开可视化，点验证完毕后自动再藏；可视化：窗口已在前台，点验证完毕不藏）；released 已释放。顶栏浏览器数等于 launching 加 occupied 加 occupying_verify，不含 queued。暂停、等批阅、AI 请求中、提交中、待回写补抽、同号还有下一份作业，一律不 released。只有本轮该号全部结束、用户停止、用户删除、不可恢复登录失败结束该生、浏览器进程死亡，才 released。禁止暂停后把名额让给排队学生。

## 9. 数据、状态与业务规则

题库表 questions（Supabase，全账号共用一份，禁止按课拆表）：

- qtype：single / multiple / judge，对应页面 data-questiontype 1 / 2 / 3
- stem：规范化前可存原文，身份计算用规范化题干
- options：jsonb，选项正文数组，不含 A) 前缀
- answer_texts：jsonb，正确选项正文或正文列表
- content_hash：unique btree，题型 + 规范化题干 + 排序后选项正文集合的 hash；作答只按它查，超时 2 秒当未命中
- course_names：text[]，出现过的课程名，GIN 索引只给浏览检索；不进身份；upsert 时追加去重
- source：import / extract / ai_verified
- verified：布尔
- conflict：布尔，两边已验证但答案不同时为真，留旧值
- updated_at：时间

身份规范化规则：去首尾空白、合并连续空白、全角转半角、去掉题号前缀 1. 与 1、，选项去掉 A) A、 A. 前缀，判断题选项统一为正确/错误。字母与 data-index 不进身份，也不进标准答案。

本机数据：加密凭据、账号列表、每号 Playwright 用户目录、待回写队列、运行日志。本机不是题库主库。不导出题库。

作业判定规则：暂无数据；客观题权重 0% 跳过；客观题权重大于 0% 进预览；非客观题跳过；100 分已批阅跳过；窗口外跳过；剩余次数小于等于 0 跳过；有续做也不续做。
浏览器名额：账号并行 N 为同时占用上限。状态有排队中、占用中、需验证占位、已释放。暂停、等批阅不算释放。顶栏浏览器数等于占用中加需验证占位的学生数。
英文状态码 queued / launching / occupied / occupying_verify / released。顶栏浏览器数还要计入 launching。
浏览器显隐：每生独立 display_mode = headless（默认）或 visual。headless 走隐藏式无头。visual 全程可见。卡片右上角切换立刻对该生已有窗口显隐，不 relaunch。

当次提交上限：无限制最多 10；有限且上限或剩余小于等于 3 则最多 1；有限且剩余大于 3 则 min(10, 剩余)；到 100 立刻停。

提交成功规则：作答历史出现提交时间更新的新记录。失败不扣次数。

待回写规则：已交卷但未完成入库或删错；该份当次不得再新开；下次该号检测或答题先补抽补删，补完再决定要不要新开。

课程行状态：检测中、无作业、已检测、满分跳过、权重0跳过、非客观题跳过、窗口外、次数用尽、需验证、待答题、回填中 x/y、题库答题 x、AI 答题 y、已提交、待回写、登录失败、提交失败、未满分下次再做。

## 11. 异常、边界与安全规则

- 账密错误、连续重登失败：停该号，其它号继续。
- IAM 验证码、人脸、微信扫码：与作业扫码同一套暂停可视化。
- 其它号继续：只指已占名额的号。排队号不补暂停名额。
- 扫码多弹窗：只扫当前可视化一个，其余取消并刷新预览。
- 一号需验证：该号暂停并继续占名额，浏览器进程不关；已占用的其它号继续。
- 未知题型：标记受阻，停止当前作业，不提交。
- AI 全模型失败：主界面显示题号、尝试数和最终原因；提交前最多补答 30 轮，第 30 轮仍失败则显示剩余题号并安全停止当前作业，明确标记未提交。
- 题库读失败：当未命中走 AI。
- 题库写失败：待回写，不卡死。
- 提交约 8 秒无弹窗：再点一次提交；仍无则失败，不扣次数，当次这份停。
- 提交失败：不以弹窗关闭为成功，不以失败记录去校对。
- 批阅超时：待回写，下次补。
- 批阅超时或查看失败：该份当次停止连刷，不得未校对就新开。
- 窗口外、次数用尽、100 分：跳过。
- 空转：分不涨且库无变化且剩余题都已 AI 失败则提前停。
- 安全：凭据仅本机加密；禁止 service role；禁止采集 data-userid、门户 URL token、学号写入仓库；日志默认开但不得写密码和 Key 全文。
- 用户停止或删除、浏览器崩溃：关闭该生浏览器并释放名额，排队学生这时才能补进。再跑不续做，该新开就新开。
- 站点提交确认绿按钮是取消，深蓝才是确定。
- 切可视化或切回无头：只允许在学生任务停止并释放上下文后按新模式重新启动；复用该生 profile 和登录态，不新开第二个上下文，不释放其它学生名额，不影响其它学生。

- 扫码：依赖用户真机微信。无头使用真实 headless:true，窗口始终不可见，二维码只通过程序内入口查看；可视化使用真实 headless:false，窗口全程可见，同时也可使用程序内二维码。点击“验证完毕”前不继续，验证不会改变浏览器模式，不新开第二个上下文。
- 扫码模式：禁止 headless:true 临时切 headed，禁止弹码时自动弹出浏览器，禁止用 CDP、最小化、负坐标或 macOS 隐藏模拟另一模式，禁止把切换按钮放进顶栏。
- 朋友使用：各自填 Key；第一期直连 Supabase anon，无多租户隔离。
- history.aspx、登录页 DOM 未成文，开发对应模块前补齐。
- 硅基流动模型 id 开发时核对控制台，以能调通的 id 为准，不把对话里的 Key 写入代码。
验收：Codex 用产品 Playwright 跑真实站点 E2E，必须全部通过。禁止 @电脑 / Computer Use。页面样式不检查。扫码与验证码由用户配合后继续。

### REQ-027 AI 全模型连通性诊断

触发条件：用户点击连通性测试或重测单个失败模型。
前置条件：模型清单已加载；请求客户端和当前 Key 配置可读取。
用户操作：启动检测、查看结果、重测失败模型。
系统行为：最多并发 3 个真实最小请求，归类结果并计算总体结论。
数据变化：仅保存本次诊断结果和检测时间，不改正式模型顺序。
状态变化：queued→running→success/failed。
正常结果：每模型结果、耗时、HTTP 和四级汇总真实可见。
异常处理：单模型失败不阻断其它模型；限流和超时单独标识。
禁止行为：禁止固定成功、模拟响应或因诊断重排答题模型。
对应 AC：AC-028。

- “连通性测试”打开模型诊断弹窗，对当前全部配置模型发送真实最小请求；默认最多并发 3 个，完成一个再补入下一个。
- 每个模型显示待检测、排队、检测中、成功、耗时和失败原因；失败类型至少区分未配置、鉴权、模型不存在、限流、网络、服务端、超时、空响应和格式错误。限流结果同时显示 Retry-After 或程序实际采用的等待时间。
- 支持单个失败模型重测；检测不得改变自动答题的模型降级顺序。
- 可用数超过一半显示“AI 服务正常”；一半或以下且多于 2 个显示“部分模型不可用”；1–2 个提示检查配置或模型；0 个显示服务不可用。结果必须带检测时间。

### REQ-030 真实无头/可视化模式与本机状态

触发条件：浏览器启动/切换/暂停/释放/崩溃或 metrics 采样。

系统行为：按任务启动前保存的模式创建真实 headless 或 headed 持久化上下文；运行中拒绝模式切换；停止释放后按新模式重新启动并复用 profile；聚合真实 metrics 和浏览器生命周期状态。
数据变化：更新运行快照，不修改业务数据或登录资料。
状态变化：窗口 hidden/visible；slot 在 launching/occupied/occupying_verify/released 间变化。
正常结果：标签与窗口一致，计数和资源状态及时准确。
异常处理：窗口或采样失败显示 unavailable/error，不沿用过期演示值。

- 创建、占用、验证暂停、释放和崩溃均须及时刷新，界面标签必须与窗口真实显隐一致。采样失败时显示 unavailable/error，不沿用过期演示值。

系统先显示解析预览、错误、重复项和预计导入数量，再显示二级确认框。确认框中的姓名、账号、密码按用户要求明文显示，确认后才复用现有账号校验与 safeStorage 写入；取消不写入任何记录。该功能必须用不含真实凭据的模拟数据 E2E 验证。

本条覆盖所有“AI 全失败或未知题型可空过并继续提交”“未作答二次确认仍点确定”的旧规则。自动答题模式不得提交任何空题。开始点击答案前先确认整卷题干和选项完整可读；提交前同时检查每题隐藏答案值和右侧答题卡 `a.e-item.active`，并精确核对多选集合。发现漏题最多补答 30 轮，补答后必须按最新选择重建复核计划。仍有漏题、未知题型或 AI 无法给出可写入答案时，停止当前作业且不提交。若站点仍弹出“部分题目没有作答”警告，程序必须点绿色取消，历史不得新增；只有正常“作业提交后将不可修改”确认允许点深蓝确定。验收见 G-ALL-22 至 G-ALL-27。

### CHG-011 AI 多模型扩容与 30 轮补答安全退出（用户确认，2026-09-20）

硅基流动候选按 REQ-013 的 14 个唯一模型顺序降级，全部共用统一高校课程客观题提示词。每个模型失败都保留原因；单轮全部失败时主界面显示具体题号、已尝试模型数和最终原因。漏题补答最多 30 轮，第 1 至 29 轮继续补答并实时显示进度；第 30 轮仍有漏题时显示剩余题号和原因，安全停止当前作业并明确标记未提交。不得静默结束，不得提交漏题卷。

### CHG-012 AI 请求节流与 429 冷却（用户确认，2026-09-20）

多学生、多课程同时产生 AI 未命中时，所有请求共用同一节流器，模型请求启动至少间隔 1.5 秒，避免瞬时高频。接口返回 429 时读取 `Retry-After`；未提供或小于默认保护值时至少冷却 5 秒。冷却只延后后续模型请求，不改变 12 秒单模型超时、14 模型降级、30 轮补答和最终安全停止规则。

### CHG-013 作答节奏优化（用户确认，2026-09-20）

本条覆盖 CHG-012 的普通请求间隔：所有学生仍共用同一 AI 节流器，但模型请求启动最小间隔调整为 0.75 秒，减少正常降级等待；HTTP 429 仍读取 `Retry-After`，且至少冷却 5 秒。题库答案成功写入页面并确认已选后，随机等待 1–3 秒再进入下一题；补答重新命中题库时同样等待。AI 回填不再额外叠加题库等待，避免重复拖慢。不得为了提速移除 429 冷却、答案写入确认、30 轮补答或未完成禁止提交门禁。

### CHG-015 稀有异常场景的真机验收口径（用户确认，2026-09-20）

题库命中后被批错并执行删库回读、站点弹出未作答警告、14 个 AI 模型全部失败并耗尽补答、待回写/云端写入失败/断网/重启补偿，仍是必须保留的产品能力和离线回归要求。完整自然 E2E 运行中一旦触发，必须验证通过或先修复再继续，禁止吞错或伪报成功。

这些场景不再要求为了验收而人工污染题库、故意留空、破坏网络或伪造服务故障。若本轮全部正常课程与作业运行结束仍未自然触发，在真机记录中写明“本轮未出现，按用户确认不阻塞”，即可完成本阶段的正常链路验收；不得把“未触发”写成“已真实通过”。

### CHG-016 每轮必须在本次运行同步校对回写（用户确认，2026-09-20）

用户发现程序在第二门课程出现待回写后释放浏览器，导致后续课程未处理。最新规则覆盖 CHG-008、CHG-009 中“停止后下次补偿”的正常运行分支：每份作业每次提交后，无论满分或非满分，都必须等待本次记录已批阅并打开历史查看，完成正确题去重入库、错误题不入库、题库错答案删除与回读确认，才算一轮完整作答。未满分且还有本轮次数时，回写成功后继续新开；达到次数上限时，回写成功后再进入下一份作业或课程。

批阅、历史读取、匹配、写入或删除暂时失败时，该学生和其持久化浏览器保持占位，在当前运行原地重试，主界面显示具体动作；不得释放浏览器、不得提前结束学生、不得进入后续课程，也不得把正常流程改成“下次再回写”。安全存储中的待回写记录只用于用户主动停止、进程崩溃或系统退出后的恢复。两个已验证答案冲突且已成功标记 conflict=true 时视为本次写回已处理，不应造成无限重试。

### CHG-017 每生可选作业重新答题次数（用户确认，2026-09-20）

本条覆盖 REQ-003、REQ-004、REQ-015、AC-015 和页面清单中固定“无限制最多 10 轮”的交互口径。学生卡片「工作模式」下方新增「作业重新答题次数」选择器，可选 1–10 轮，按学生独立加密保存，默认 10 轮；旧账号缺字段时按 10 轮兼容。用户测试时可选 2 轮，后续无需改源码即可自行切回 10 轮。无限制作业以所选值为本次上限；有限作业仍优先遵守站点剩余次数与“上限或剩余不超过 3 时只做 1 轮”的安全规则，剩余大于 3 时取所选值与剩余次数的较小值。正在运行的作业不热改本轮计划，下次登录并刷新课程后生效。
