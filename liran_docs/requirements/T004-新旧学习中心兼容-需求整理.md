## 用户想解决的问题

学校更新学习中心后，部分账号登录进入新版未来学习空间，另一些账号仍进入旧版学习中心。目前程序只有旧版入口和课程扫描，可能把新版正常登录误判为失败，或无法取得课程、进入形考作业。

本次只新增新版入口分支，让新旧版同时可用。进入形考作业后仍是现有旧站页面，扫码后的作答界面没有变化。

## 已明确的需求与边界

### 自动识别与登录收尾

- 同一个程序自动识别账号实际落到的新旧学习中心，不要求用户手动选版本，不维护账号与页面版本的固定白名单。
- 保留现有 IAM 登录、旧版门户网关处理、会话复用和验证门禁；只补齐新版页面就绪识别及进入学习页的步骤，不重写学校认证协议，不伪造 token。
- 旧版目标仍为 `learning.shou.org.cn/scenter` 和原有课程 Tab；新版为 `aiedu.shou.org.cn` 首页及 `/learning`。实际登录重定向链必须在真机验证后再确定，不凭截图替换全局登录入口。
- 新版落在首页时点击主导航的学习按钮；已在学习页时等待真实课程区域就绪。不能因为没有 `#tab-courseList` 而判新版登录失败。
- 仅出现新版页面壳不能代表课程已加载；需要区分加载中、正常空态、读取失败和已就绪。

### 课程扫描与入口

- 旧版继续保留 Tab 内课程和独立置顶形势与政策课程的合并、顺序及课程身份去重；收藏课程不纳入扫描。
- 新版从左侧课程卡读取课程名与实际列表顺序，不能只取视口内可见卡片，不能写死课程数量。当前样本 8 门含形势与政策，其它账号是否分页或虚拟列表需验证后决定处理方式。
- 新版逐门切课，等加载完成和对应课程容器出现，再定位形考任务；不得读取上一门课残留内容。共享同一中栏的切课与入口采集必须避免并发争抢。
- 准确点击 `去完成：完成课程形考作业`，接住新标签并确认到达旧站 `HomeWorkNew.aspx`。不点击在线学习、成绩查询入口，也不点击我已完成／我已知晓修改任务状态。
- 当前任务不在进行中时，按实际页面核对已完成／已逾期筛选；这些筛选只改变展示，不改变任务完成状态。DOM 是带 `aria-pressed` 的按钮，空态没有内部 role=list。
- 新版 course-ref 是不透明标识，不能作为旧站 courseOpenId。旧站课程参数从真实链接／跳转结果取得，兼容参数名大小写并核对当前课程身份。
- 用既有课程身份规则去重，课程名相同不能直接合并；各账号独立扫描、独立展示和执行，不互相覆盖。
- 左侧学习百分比、右侧学习进度和右栏暂无作业都不能作为跳过真实形考列表的依据。
- 缺少形考入口、切课失败、跳转错误或课程身份不匹配时给出明确且脱敏的失败原因，不能把半份课表或接口失败伪装成扫描成功／无课程。
- 临时标签由程序正常关闭并释放；不误关其它账号或用户标签。课程列表取得后尽量沿用已有检测返回类型和后续调度，不新增平行答题实现。

### 进入旧站后的共用流程

- 两种学习中心最终复用现有形考列表、网上记分作业与阶段性测验判定、作业预览和已有历史状态读取。
- 继续保留现有课程范围、工作模式、满分跳过、日期窗口、次数上限、扫码闸门、失败隔离、停止及名额释放规则。
- 新旧中心取得的课程应能正常进入现有答题模式及提取模式的课程检测；本任务不为提取验收写入真实题库。
- 不新增 UI 壳，不重做程序工作台和学校网页样式。真机检查关注现有产品入口、课程及作业展示、运行状态和程序内扫码等待是否正确。
- 不改扫码后的答题、AI、保存、提交、批阅、题库回写逻辑，不把旧任务尚未收口的题型问题并入 T004。

## 当前形成的用户流程

旧版：启动检测 → IAM／复用会话 → 旧版我的课程及置顶课 → 课程目录 → 形考作业 → 原有作业预览与状态判定 → 对合法可作答样本进入扫码等待。

新版：启动检测 → IAM／复用会话 → 新版首页 → 学习 → 左侧逐门切课 → 完成课程形考作业的去完成 → 新标签旧站形考列表 → 原有作业预览与状态判定 → 对合法可作答样本进入扫码等待。

扫码前测试终点按本轮理解定义为：能由程序真实入口触发扫码验证并显示等待扫码，随后停止测试；不实际扫码，不点击验证完毕放行，不进入扫码后的答题、保存、提交和批阅。若已有会话已经验证，则用隔离的未授权测试会话验证门禁，不能冒充本轮扫码成功。
