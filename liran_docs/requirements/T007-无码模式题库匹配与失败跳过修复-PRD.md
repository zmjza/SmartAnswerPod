## 1. 产品/功能概述

T007 修复无码答题模式中“题库已有题但匹配失败”、失败后全局暂停、队列不续流和多并发页面异常的问题。无码模式只处理客观题：普通单选、多选、判断、下拉/选择填空，以及大学英语语法、听力、完型、阅读和 Picker。

普通填空题、简答题、问答题、论述题、主观题、富文本题和文件上传题全部不属于本模式支持范围。当前作业只要出现任一无可靠客观控件结构的题目，就隔离整份作业，不提交残缺试卷，不等待人工长时间占用账号，并在有界收口后继续后续作业、课程和账号。答题卡标题只用于分区提示，整卷必须在首题保存前逐题位读取真实控件；标题伪装成客观题也不能绕过隔离。复合题答题卡按同题型 occurrence 和真实 `group.position` 定位，禁止使用全局 `cardIndex`；缺少页面题号 x/y 或没有答题题组容器时，仍必须按可见文本控件和真实结构 fail-closed。

英语“完型填空/完形填空”保持 `english_cloze` 客观题；“选择填空题”仅在真实 radio/checkbox 控件可唯一判型时按客观单选/多选处理。

## 2. 背景与问题

1. 大学英语（3）题库已有数据但身份匹配失败，Picker、完型等真实题型码与旧题库口径不一致。
2. 部分作业含普通填空题、简答题或机械课程主观新题型；此前尝试扩展文本题、AI 文本和文件上传，增加复杂度且不符合最终范围。
3. 检测或答题失败进入 `needs_user` 后可能全局暂停，后续账号长期排队。
4. 多并发时部分账号可能卡在空白/加载页，关闭和补位不及时。
5. 答题页已有进度后绝对禁止刷新；但非答题页需要 60/90/120 秒分级有界恢复。
6. 客观题交卷前最后一次保存后，页面可能短暂 blank/loading；必须避免在页面未稳定时误判为可交卷或全局人工中断。

## 3. 用户与使用场景

1. 运行大学英语（3）作业，题库已有客观答案时优先命中；题库无可靠行时按既有规则转 AI。
2. 运行纯客观作业，逐题保存、答题卡核对、交卷、取分；不满分按既有重答规则继续。
3. 运行含普通填空题或简答题的作业，系统识别为非客观题并隔离整份作业，不点击错误选项、不提交不完整试卷。
4. 运行机电一体化系统设计，遇到新主观题、富文本或文件题时直接跳过该作业；不为该题型生成文本或上传文件。
5. 一个账号完成、失败、跳过或停止后，下一名 queued 账号自动补位。
6. 多账号、多课程并发时，账号和课程页面互不串用，峰值不超配置，最终队列、浏览器和上下文归零。

## 4. 产品目标

- 修复大学英语五类客观题的题库身份兼容和只读命中。

- 主观、文本、富文本、文件题整份作业隔离，不生成、不填写、不保存、不交卷。
- 失败恢复有界，当前作业/课程失败后可继续其它项，账号槽位和队列正常释放。
- 题库严格 GET-only，不写回、不校对、不提取、不新增待回写。
- 答题页零刷新；非答题页按 60/90/120 秒规则最多恢复 3 次。
- 全功能、并发、旧模式、构建和敏感扫描通过后完成 2.9 交付；2.9 最终包已重打并回填 SHA、签名、架构和包内敏感扫描，随后提交和推送。

## 8. 功能需求

### REQ-001 大学英语客观题身份兼容

触发条件：无码学生进入大学英语语法、听力、Picker、完型或阅读作业。
前置条件：页面已加载真实题组，且当前题属于已支持的客观题类型。
用户操作：用户启动无码学生，无需逐题操作。
系统行为：优先读取真实 `data-questiontype`；完型按外层 `9`、阅读 `8`、听力 `11`、Picker `7`、语法按普通单选；复合题保留共享材料、父题型码、子题序号/槽位和规范化选项正文；主身份未命中时按有界候选身份只读查询题库。答题卡定位必须使用逻辑题组真实 `group.position`，不得用页面中第几张答题卡的全局 `cardIndex` 代替题目位置。
数据变化：记录题型、题位、题库/AI 来源和脱敏身份诊断，不写题干正文或真实 ID。
状态变化：`reading_questions -> bank_lookup -> answering`，身份冲突或无法唯一映射时进入当前作业隔离。
正常结果：题库已有客观答案时命中并映射到当前页面选项；题库无可靠行时按既有规则转 AI。
异常处理：冲突、字段缺失、重复行、题型不符、共享正文差异无法收敛或候选不唯一时停止当前作业，不猜答案。
禁止行为：按字母、选项位置、默认项、题号或课程名猜答案；伪造 Picker 题库命中；写入题库。
对应 AC：AC-001。

### REQ-002 只读题库冲突拒绝

触发条件：当前客观题进入题库查询流程。
前置条件：只读题库客户端可用，并且当前题目身份候选已生成。
用户操作：无。
系统行为：查询 `conflict`、题干、共享材料、选项正文和题型；批量候选去重并受作业级预算和缓存约束；仅当唯一可靠行可映射到当前选项时返回答案。
数据变化：记录 GET 计数、命中/未命中、冲突和候选数量；不写题库、不新增待回写。
状态变化：`bank_lookup -> bank_hit | bank_miss | bank_invalid`。
正常结果：合法且唯一的题库答案进入作答计划。
异常处理：网络失败、空 options、冲突、多行、题型不符或映射不唯一时 fail-closed，按既有规则转 AI或隔离当前作业。
禁止行为：`POST/PATCH/PUT/DELETE/OTHER`、upsert、删库、校对、提取或写回。
对应 AC：AC-002。

### REQ-003 仅客观题范围与非客观题整份隔离

触发条件：作业题组读取过程中发现可见 textarea、文本 input、contenteditable、富文本、文件控件或未知主观结构。
前置条件：当前处于无码模式的作业读取或作答准备阶段。
用户操作：无；用户可停止当前任务。
系统行为：在首题作答和保存前打开答题卡，按题位逐个读取真实控件；每张可见答题卡至少有一个可点击题位，目标题位必须有明确数字题号并与当前题目位置正向匹配，空壳卡或非数字题号不能放行；任一题位出现非客观控件或未知结构时立即将当前整份作业标记为非客观题不支持；完成结构检查后回到第一题再开始作答。扫描当前题型时排除已展开答题卡的标题子树，避免卡面标题污染题型判断。复合题答题卡必须按同题型 occurrence 与逻辑题组真实 `group.position` 定位，不能使用全局 `cardIndex` 或让第二张未导航卡复用第一组局部题号；缺少页面题号 x/y 时不得仅凭局部题号、卡片顺序或默认位置补齐，必须 fail-closed。即使没有 `.question-card` 等答题题组容器，当前题面可见 textarea、文本 input、contenteditable 或文件控件也必须被扫描并整份隔离。答题卡入口被短暂动画遮罩覆盖时，必须在答题卡总时限内保持页面不动、等待遮罩消失后重试，不能用程序化点击绕过命中测试；永久遮罩仍有界失败。复合题第一篇必须支持页面题号 `1 -> 2` 的到达证据，但不能把第二篇答题卡的当前态冒充成第一篇目标行。不生成 AI 文本、不填写、不保存、不交卷；释放当前作业并继续其它作业、课程和账号。
数据变化：记录脱敏的不支持原因和 `skip_non_objective` 计数，不记录题面、答案正文或文件地址。
状态变化：`reading_questions -> unsupported_non_objective -> skipped`。
正常结果：客观题作业继续作答；非客观题作业无保存、无 Finish、无题库写。
异常处理：未知控件、混合控件、空壳答题卡、缺少明确数字题号或页面 x/y、不能证明同题型 occurrence、没有题组容器却出现可见文本控件时，均按 fail-closed 处理，不尝试猜测结构。
禁止行为：恢复主观题 AI 文本、`answerContent` 主观保存、教师批阅等待、文件上传、多字段主观答题卡或部分交卷。
对应 AC：AC-003。

### REQ-004 有界恢复和失败跳过

触发条件：登录、首页、课程、作业列表或答题启动页出现空白、页面错误、重复心跳或持续活动请求；或检测/作答返回普通失败。
前置条件：页面尚未被判定为已有作答进度的答题页。
用户操作：无；用户可随时停止。
系统行为：非答题页按 60 秒无活动、90 秒重复心跳、120 秒活动请求执行有界恢复，最多 3 次；答题启动页无进度可有限返回重进；已有进度答题页不刷新、不自动重进，慢响应继续等待，技术安全线后收口为当前作业失败或结果不确定。
数据变化：记录页面分类、恢复次数、等待时长和脱敏错误码。
状态变化：`blank/loading -> recovering -> continue | skipped | stopped`；答题页异常只能进入 `isolated/uncertain/stopped`。
正常结果：普通失败在预算内恢复；预算耗尽后跳过当前对象并继续队列。
异常处理：登录失败跳当前账号，课程失败跳当前课程，作业失败跳当前作业，提交结果不确定时禁止重复交卷。
禁止行为：答题页刷新、自动重进已有进度页、固定短超时误杀慢响应、失败后全局暂停或伪造成功。
对应 AC：AC-004。

### REQ-005 队列与并发续流

触发条件：任一账号或课程进入正常完成、失败、跳过、主动停止、提交不确定或浏览器关闭终态。
前置条件：该账号/课程曾被调度器接受，存在或曾经存在运行任务。
用户操作：可停止指定账号或全部停止。
系统行为：释放容量后主动唤醒队列；队列按本轮 FIFO 提升；closing 仍占容量，确认物理关闭后才补位；释放、重复停止和晚到 acquire 必须幂等；账号并发和课程并发峰值不得超过配置。
数据变化：同步 `activeRuns`、stop token、槽位、held、queued、浏览器上下文和活动课程页计数。
状态变化：`queued -> launching -> occupied -> closing -> released`；停止后的 queued 不得晚到启动。
正常结果：后续账号自动补位，页面和会话不串号，最终 queue/browser/context/active course page 为 0。
异常处理：启动或关闭失败安全释放自身容量；单账号失败不阻塞其它账号。
禁止行为：只靠轮询补位、重复启动、重复占用、长期 queued、关闭中提前开新浏览器或降低并发掩盖问题。
对应 AC：AC-005。

触发条件：T007 功能实现和定向修复完成，准备进入最终验收。
前置条件：功能代码冻结，测试夹具和真实账号可用；版本元数据已进入 2.9 交付阶段。
用户操作：Codex 执行离线、真实站点、headless/visual 和旧模式回归。
系统行为：运行 T005、P0、T006、T007、E3、UI、build 和旧 `answer/extract` 回归；使用真实产品完成登录、课程/作业检测、普通客观题、英语五类、保存、答题卡、交卷、取分、低分重答、3 秒节奏、三项作业时长、失败跳过、空白恢复和题库零写入；执行账号并发 `1/2/3/4/5/6/8`、课程并发 `2/3/4/5/6/8`、可视化 2、9/9 账号和自然非客观隔离。
数据变化：只写脱敏测试记录、计数、耗时和结果；不写真实凭据、题干、答案正文或完整业务 ID。
状态变化：`development -> regression -> acceptance_passed | blocked`。

异常处理：任一失败保留脱敏失败日志，修复后复跑同一项；不得用成功日志覆盖历史失败。

对应 AC：AC-006。

## 9. 数据、状态与业务规则

- 题型枚举只保留 `single`、`multiple`、`judge`、`picker`、`english_grammar`、`english_listening`、`english_cloze`、`english_reading`、`unknown`。
- 客观题判型必须以真实控件为准：单选和判断使用 radio，多选使用 checkbox；选择填空只有控件角色一致时才可判型，混合控件 fail-closed。
- 作业读取一旦发现可见文本控件、contenteditable、文件控件或未知主观结构，当前整份作业进入 `unsupported_non_objective`，不得产生主观保存、交卷或题库写。
- 客观题保存必须同时满足新请求、HTTP/业务成功、页面推进或严格答题卡组证据；慢响应继续等待，不重复点击，不刷新已有进度答题页。
- 非答题页固定使用 60 秒无活动、90 秒重复心跳、120 秒活动请求和最多 3 次恢复；答题启动页无进度才允许有限返回重进。
- 调度状态固定包含 `queued / launching / occupied / closing / released`；closing 占用容量，只有物理关闭确认后才允许唤醒下一名。
- 日志只保存别名、状态、枚举、计数、耗时、脱敏错误码和短指纹，不保存账号、密码、AI Key、Cookie、token、完整 URL、真实业务 ID、题干、答案正文或文件地址。

## 10. 页面与 UI 需求

不新增独立页面、不新增视觉方案、不改工作台主题和布局。沿用现有工作台学生卡、课程/作业行、状态日志和底部控制：

- 每个学生的账号并发、课程并发、queued/launching/occupied/closing/released 状态必须真实反映调度，不得把 queued 显示成运行中。
- 客观题作业显示题号/总数、题库/AI 来源计数、保存/交卷/取分/重答、平均每题、最长单题和作业总时长，时间统一为“X分YY秒”。
- 非客观题作业只显示“不支持/已隔离”及脱敏原因，不显示文本填写、文件上传、教师批阅或“分数待确认”。
- 失败后显示当前对象、错误分类和是否继续队列；停止后不得出现晚到启动或伪造成功。
- 不显示题干、答案、真实 ID、完整 URL、凭据或题库写入统计。

## 11. 异常、边界与安全规则

- 登录失败跳当前账号；课程检测失败按预算重试后跳当前课程；作业打开、读取或保存失败按预算重试后跳当前作业；提交结果不确定时禁止重复交卷并继续后续账号。
- 答题页已有进度时绝不刷新、不自动重进、不重建上下文；慢响应由既有 240 秒技术安全线收口，达到上限只保留页面和安全停止。
- 无码题库严格 GET-only；任何写请求、upsert、删除、校对、提取或待回写新增均为阻断。
- 冲突、空 options、重复行、题型不符、候选不唯一、文本/文件控件和未知主观结构都必须 fail-closed，不猜答案、不提交残缺卷。
- 真实账号只在运行时读取；不把账号、密码、AI Key、Cookie、token、完整 URL、真实 workId/paperId、题干或答案正文写入文档、日志、截图或提交。
- 不删除项目外文件，不触碰 `.codex-backups/`，不 reset/checkout 用户修改，不 force push，不执行 Release、Tag、OTA 或安装包上传。

## 12. 兼容性与限制

- 旧 `answer/extract` 的登录、授权、检测、作答、提交、批阅、题库回写和待回写语义不得改变；旧业务不得 import noqr，noqr 不得依赖旧业务状态机。
- 共享浏览器池、槽位和调度改动必须同时通过旧模式回归；任何旧模式行为变化都是阻断项。
- 真实站点慢响应和空白具有不确定性；未自然出现的错误密码、人工验证、漏题确认和 Finish 异常只能保留内部覆盖，不得写成真机通过。
- Windows 只做构建、架构和静态核验，不声明 Windows 真机安装通过。
- 不新增 UI 视觉页面；工作台只调整状态消费和文案，不改已有设计语言。
