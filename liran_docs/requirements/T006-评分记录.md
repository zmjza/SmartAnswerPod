## 评分证据

- `electron/core/slot-pool.ts` 原实现只有槽位状态，`promoteQueued()` 只修改状态；T006 必须补 FIFO、关闭阶段和幂等释放。
- `electron/pool.ts` 负责持久化浏览器上下文；释放槽位与上下文关闭的顺序会影响真实并发上限。
- `electron/noqr/run.ts` 负责 `activeRuns`、`stopControllers`、`stopFlags`、排队等待和选课启动 token；生命周期竞态直接影响用户看到的“排队中”。
- `electron/noqr/session.ts` 的唯一登录入口、首次导航、空白 gate 和答题页禁刷新规则必须同时保持。
- `tests/t006-scheduler.test.mts`、`tests/e2e-browser-pool.mjs`、`tests/t005-real-product.mjs` 现有覆盖不足以证明失败、停止、关闭、两批流转和多账号完整作答，因此验证复杂度按最高档计。
- 当前 T005 全量、P0、E3、UI 和构建已有基线，但本轮修改后必须重新运行；真实账号只在运行时从目标文件读取。
- 用户补充的非答题页 60/90/120 有界恢复、自然现象真机边界、账号/课程并发 2/3/4/5/6/8 矩阵已纳入 REQ-004、AC-001/AC-002/AC-004 和测试追踪；当前交付目标明确要求版本 2.8、本地 macOS ARM64/Windows x64 包、源码提交和 `origin/main` 推送，这些属于完成条件，不得用旧 2.7 证据替代。

## 安全门禁

- 无码题库严格 GET-only；任何 `POST/PATCH/PUT/DELETE/OTHER`、`writeAttempts` 或本机待回写新增都是阻断项。
- 答题页绝不刷新、自动重进或重建已有进度页面；非答题页采用 60 秒无活动静默、90 秒重复活动上限、120 秒活动请求上限和限定刷新/返回预算。
- 不降低 `account_parallel` 或 `course_parallel` 来规避问题，不跳过排队账号，不把失败或停止写成成功。
- 不写入或输出账号、密码、AI Key、Cookie、token、完整 URL、真实 workId/paperId、题干或音频地址。
