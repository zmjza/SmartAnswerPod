## 1. 产品/功能概述

T006 修复无码答题模式在多账号并发和队列流转中的可靠性问题。可视化浏览器在账号并发 2 时必须启动两个相互独立的持久化上下文，每个账号拥有独立登录会话、页面、网络观察和空白恢复计时；一个账号结束后，下一名排队账号必须自动进入启动流程。修复不改变无码答题的题库优先、AI 兜底、保存、交卷、取分、重答、题库零写入和答题页禁刷新规则，也不改变旧扫码答题和提取题库的业务行为。

## 2. 背景与问题

用户实际运行发现两种阻断：第一，可视化模式开启账号并发 2 时，第一个账号正常，第二个账号可能在空白页停留 100～200 多秒；第二，一轮账号结束后，下一轮账号长期显示“排队中”，需要人工操作。进一步代码审计发现首次登录导航可能阻塞空白恢复、队列只依赖 400ms 轮询、选课启动状态跨批次粘连、槽位释放早于上下文关闭、停止与浏览器获取完成之间存在晚到启动竞态。用户已确认真实站点存在登录/保存慢响应和偶发空白，因此不能通过固定短超时、刷新答题页或降低并发来掩盖。

## 3. 用户与使用场景

用户在工作台为多个学生配置无码答题模式，设置账号并发和课程并发后启动一轮任务。典型场景包括：

1. 3 个学生、账号并发 2，在可视化浏览器中同时启动前两个学生。
2. 两个学生各自从唯一登录入口进入首页并处理课程；第三个学生保持排队。
3. 任一学生正常完成、失败、被用户停止或浏览器关闭后，第三个学生自动补位。
4. 两批以上账号连续运行，用户不需要刷新、重启或再次点击开始。
5. 非答题页出现无活动空白时按既有预算恢复；答题页已有进度时只等待或停止，绝不刷新。
6. 全账号真实运行仍优先题库，题库缺失时调用 AI，最终交卷取分且题库只读。

## 4. 产品目标

- 可视化模式下正确支持至少两个独立持久化浏览器上下文，互不阻塞。
- 队列释放后由中央释放通知主动唤醒补位，轮询只作为兜底；支持正常完成、失败、主动停止、上下文关闭和启动失败。
- 队列按本轮实际入队顺序 FIFO；同一账号不得重复启动、双重占用或重复释放。
- 选课启动状态按学生和批次隔离，旧批次仍在运行不能阻塞后续批次开始选课。
- 浏览器关闭期间仍占用容量，关闭完成或安全收口后才释放并补位；停止不得晚到启动。
- 登录/首页首次导航失败或慢响应时有界恢复，但答题页绝不刷新。
- 保持无码题库 GET-only、旧 `answer/extract` 零业务回归、全部账号真实闭环。
- 最终版本升级到 2.8，完成本地 macOS ARM64 和 Windows x64 打包、源码提交与 `origin/main` 推送。

## 7. 用户流程

```text
工作台选择无码答题和账号并发 2
  -> 启动多名学生
  -> 前两名 queued -> launching -> occupied
  -> 第三人保持 queued
  -> 任一前序学生完成/失败/停止/关闭
  -> 释放容量并通知排队学生
  -> queued -> launching -> occupied
  -> 继续登录、课程检测、作答、保存、交卷、取分
  -> 全部学生 released，队列和浏览器归零
```

选课模式下，前一名学生开始执行后仍保留本批次 token；后续排队学生进入等待选课后，必须能够独立开始，不因上一名仍在运行而被误报“正在扫描”。

## 8. 功能需求

### REQ-001 可视化多并发独立上下文

触发条件：用户启动至少两个无码学生，且 `account_parallel` 不小于 2。
前置条件：账号已保存，浏览器 profile 可创建，工作模式为 `noqr`。
用户操作：在工作台点击开始或运行一轮。
系统行为：每个账号按学生隔离持久化上下文、页面、登录会话、网络活动、空白恢复 gate 和运行状态；浏览器启动、窗口排布和 CDP 不得共享可变锁。
数据变化：记录账号槽位、浏览器上下文数、活动页面数和运行诊断，不记录凭据或真实 ID。
状态变化：`queued -> launching -> occupied -> closing -> released`，任一账号的状态不得驱动其它账号的页面状态。
正常结果：两个独立上下文同时存在并分别完成登录或后续流程，峰值不超过配置上限。
异常处理：单个上下文启动失败释放自己的容量并记录脱敏错误；其它账号继续。
禁止行为：共享活动页面、将第二账号误判为心跳或空白完成、降低并发或串行伪并发。
对应 AC：AC-001。

### REQ-002 中央释放补位与幂等生命周期

触发条件：任一占用中的账号正常完成、失败、主动停止、浏览器关闭或启动失败。
前置条件：该账号曾被槽位池接受，且存在或曾经存在运行任务。
用户操作：无需用户操作；停止按钮只负责发停止信号。
系统行为：释放事件主动唤醒队列；队列按本轮 FIFO 提升；释放、关闭和任务收尾重复发生时只允许一次容量转换和一次补位尝试。
数据变化：同步 `activeRuns`、`stopControllers`、`stopFlags`、`slots`、`held` 和 queued 状态。
状态变化：正常和异常终态都必须进入 `closing` 后 `released`；排队账号不得在停止后晚到启动。
正常结果：3 个学生并发 2 时，前两个启动，第三个排队；任一前序结束后第三个自动启动；最终所有账号 released、queued 为 0、浏览器为 0。
异常处理：启动失败或关闭超时安全释放容量；重复释放不重复提升；停止全部中断排队等待。
禁止行为：只靠 400ms 轮询、重复启动、双重占用、长期占用已关闭浏览器或手动点击补位。
对应 AC：AC-002。

### REQ-003 选课批次隔离

触发条件：course_scope 为 selected，且存在排队或旧批次运行中的账号。
前置条件：当前账号已扫描课程并进入等待选课。
用户操作：选择课程并点击开始执行。
系统行为：选课启动 token 按学生保留到本轮结束；queued 和 released 账号不计为正在扫描；后续排队账号拥有独立启动 token，不被旧批次已开始状态永久锁死。
数据变化：每个学生的 awaitingCourseSelection、selectedCourseKeys、启动 token 和运行状态。
状态变化：waiting_course_selection -> detecting/opening_homework；已启动账号不被误判为等待扫描。
正常结果：前两名开始执行后，第三名释放容量后可独立进入选课并开始；旧账号仍在运行时也不阻塞。
异常处理：没有选择课程、没有等待学生或重复开始都返回明确错误，不伪造成功。
禁止行为：全局布尔锁、把 queued 当扫描中、跨学生复用选课状态。
对应 AC：AC-003。

### REQ-004 登录导航与非答题页停留/空白恢复

触发条件：登录/首页首次导航失败、迟迟不 commit、页面无内容或非答题页无活动空白。
前置条件：账号尚未进入答题页，或页面明确不是已有进度的答题页。
用户操作：无；系统按恢复预算自动处理，用户可停止。
系统行为：登录/首页导航使用可观察的 commit/空白 gate；非答题页采用 60 秒无活动静默宽限、90 秒重复短活动上限、120 秒活动请求上限和限定刷新预算；有活动请求仍优先等待真实响应，达到非答题安全上限后才刷新或返回；答题页刷新入口必须集中拒绝，答题页只允许既有 240 秒技术安全收口，不以该规则刷新。
数据变化：记录导航等待、空白观察、刷新次数和页面分类，不记录完整 URL。
状态变化：blank/unknown -> login/home 或明确 `blank_page`/`page_error`；答题页异常保留页面。
正常结果：首次文档失败或慢响应后可在有界时间内继续登录；真正慢响应不被固定短超时杀掉。
异常处理：活动请求超过安全上限、刷新预算耗尽或页面明确错误时安全停止当前学生。
禁止行为：答题页刷新、自动重进已有进度页、把所有请求都当心跳、无限等待或固定超时刷新。
对应 AC：AC-004。

### REQ-005 无码答题完整业务与旧模式隔离

触发条件：无码学生进入课程、作业或答题页。
前置条件：已获得作业入口，AI 凭据和只读题库可用或能明确失败。
用户操作：用户启动后无需逐题操作。
系统行为：题库优先、题库缺失 AI 兜底；保存必须同时满足请求、响应和页面推进证据；交卷、取分、重答和停止沿用 T005 规则；题库只读。
数据变化：记录题位、来源计数、作业时长、分数和脱敏日志，不写题库或待回写队列。
状态变化：课程/作业状态按真实检测、作答、保存、交卷、取分收口；失败只隔离当前作业/课程。
正常结果：所有真实别名完整走登录、检测、作答、保存、交卷、取分、释放；题库 GET 有记录、写请求为 0。
异常处理：慢响应继续等待；已有进度答题页异常时保留页面；单作业失败不伪造整轮成功。
禁止行为：题库写、答题页刷新、跳过真实作答、把停止/失败标为完成、改动旧 `answer/extract`。
对应 AC：AC-005。

## 9. 数据、状态与业务规则

槽位状态固定为 `queued / launching / occupied / occupying_verify / closing / released`；`closing` 仍占用容量，不能提升下一名。队列以本轮单调入队票号排序，释放事件和 400ms 兜底只能触发同一个幂等补位路径。`activeRuns` 删除与 `stopControllers`/`stopFlags` 清理必须在任务 finally 收口，但浏览器关闭不得无限期阻塞全局运行锁。

无码业务继续保持题库 GET-only；保存、交卷、取分和重答沿用 T005 的证据规则。答题页保护优先于任何空白恢复；已有进度的页面异常一律保留页面并收口为需人工处理或停止。所有日志只保留别名、枚举、计数、耗时和安全诊断，不写凭据或真实业务文本。

## 10. 页面与 UI 需求

不新增视觉页面，不重做工作台。工作台和账号页必须正确显示每个学生的 queued、launching、occupied、closing、released 状态；排队数量不包含占用数，浏览器数量与真实上下文一致。停止按钮必须作用于目标学生，不能因为其它账号补位而误停或误启动。错误、空白、停止和释放状态必须真实呈现，不能用成功文案覆盖。

## 11. 异常、边界与安全规则

- 浏览器启动失败、上下文关闭、页面关闭、重复释放和重复停止必须有幂等收口。
- 登录首次文档失败可按非答题页预算恢复；有活动慢请求继续等待，答题页禁止刷新。
- 停止全部时排队任务立即失效，不得在停止后启动或占用容量。
- 无码题库只读；任何写请求、回写队列新增或旧模式行为变化为阻断项。
- 真实账号、密码、AI Key、Cookie、token、完整 URL、真实 ID、题干和音频地址不得进入文档、日志、提交或回复。
- 不降低并发配置、不跳过账号、不把真实空白判为正常完成。

## 12. 兼容性与限制

旧 `answer/extract` 的登录、扫码、题库读写、提交、批阅、回写和状态机保持原样；共享浏览器池的改动必须由 P0、build、旧模式 E2E 和真实回归验证。Windows 只完成构建和静态核验，不声明 Windows 真机安装通过；真实站点慢响应无法人为保证每次出现，未自然触发的分支只能保留内部覆盖并明确标注。

## 14. 验收标准

### AC-001 可视化双并发

对应需求：REQ-001。
验收步骤：使用真实产品、3 个学生、可视化、`account_parallel=2` 启动；观察两个上下文、登录请求、页面分类和槽位快照。再对账号并发 2/3/4/5/6/8 分别执行设置矩阵，验证每个配置都达到配置峰值、不得超过峰值，并在退出后回落到 0。
预期结果：前两个账号独立启动并登录/推进，第三个 queued；峰值上下文等于配置并发且不超过配置；矩阵中每个配置都无串号、无长期空白、无浏览器或上下文残留。
失败条件：第二账号长期空白、共享页面、串号、超并发或仅凭状态文案判通过。

### AC-002 自动补位与终态

对应需求：REQ-002。
验收步骤：覆盖正常完成、失败、主动停止、上下文关闭、重复释放、全部停止和两批以上账号；账号并发覆盖 2/3/4/5/6/8；观察队列状态、浏览器关闭、测试进程退出和最终释放。
预期结果：任一真实终态只启动一次下一名；queued 自动转 launching/occupied；停止后不晚到启动；最终所有账号 released、queued=0、浏览器=0、活动上下文=0，测试进程和产品主进程均能正常退出。
失败条件：下一名永久排队、重复启动、重复释放、停止后补位、关闭中提前开新浏览器或运行锁永久占用。

### AC-003 选课批次隔离

对应需求：REQ-003。
验收步骤：3 个 selected 账号并发 2，让一名旧批次账号保持运行，另一名结束后让第三名进入选课并点击开始；课程并发另按 2/3/4/5/6/8 设置矩阵验证生产接线峰值与回落。

### AC-004 登录与空白恢复

对应需求：REQ-004。
验收步骤：使用真实产品可自然观察到的登录文档慢提交、非答题页无活动空白、活动慢请求和已有进度答题页；同时观察刷新次数与页面分类。内部夹具只用于补充边界，不计入真机通过。规则必须分别为 60 秒无活动静默、90 秒重复短活动、120 秒活动请求和限定恢复预算。
预期结果：非答题页按三类预算恢复或继续等待慢请求；答题页加载次数保持不增加，异常安全收口；活跃慢请求不按静默空白提前刷新。
失败条件：答题页刷新、自动重进、固定短超时误杀慢响应、无限等待或把空白当完成。

### AC-005 无码完整业务与零写入

对应需求：REQ-005。

失败条件：跳过账号、只测登录、题库写、答题页刷新、慢响应误杀、失败当成功或旧模式业务变化。

失败条件：提前升版、测试失败、产物夹带敏感信息、Windows 真机伪报、force push、Release/Tag/OTA 或提交构建产物。
