## 1. 产品/功能概述

在现有“答题 / 提取题库”工作模式之外新增第三个独立模式“无码答题”。该模式面向 `coursework.shou.org.cn` 的无扫码登录和逐题答题页面，完整继承现有答题模式的学生、课程、运行和配置能力；核心业务差异是使用新站无扫码入口，并在完成答题后不执行任何题库回写、校对、提取或待回写补偿。

## 2. 背景与问题

学校新增的在线学习平台提供可直接以用户名和密码进入的答题入口，不经过既有扫码授权链路。现有程序的答题模式和提取题库模式均围绕旧站扫码流程构建，无法直接覆盖新站登录、课程菜单、作业列表、逐题作答和记录出分页面。

新站存在明显慢响应：登录可能持续数十秒，单题或整组答案保存可能等待数十秒到数分钟，偶发页面空白。刷新答题页会丢失已作答进度，因此不能沿用固定业务超时或刷新恢复策略。需求必须在不改动现有扫码答题和提取题库逻辑的前提下，以独立模块、独立页面契约和独立运行状态承接。

## 3. 用户与使用场景

用户是现有桌面程序的个人用户或多学生账号管理者。用户在同一工作台维护学生账号，为每个学生独立选择执行环境、工作模式、课程范围、重新答题次数等配置。

典型流程：

1. 用户把学生工作模式切换为“无码答题”。
2. 程序从唯一登录页进入新站，使用现有账号密码或复用持久化会话。
3. 程序点击“形考作业”，读取课程菜单并逐门检测作业。
4. 程序按现有答题模式规则选择作业，优先查题库，未命中调用 AI。
5. 程序逐题或按复合组保存答案，等待真实请求和页面推进。
6. 程序交卷、读取最新有效分数，并按现有满分/重答规则决定是否重答。
7. 全过程不写题库，不进入旧扫码验证，不影响其它学生和两个既有工作模式。

## 4. 产品目标

- 新增独立 `noqr` 工作模式，界面名称为“无码答题”。
- 完整继承答题模式现有配置和运行能力。
- 在新站完成登录、课程/作业检测、作答、保存、交卷、出分和未满分重答。
- 使用“真实请求 + 真实响应 + 页面推进/成功提示”的可靠保存判定。
- 慢响应期间不按固定业务秒数刷新、重进或重复提交；登录、保存、交卷等操作按真实响应推进，并受 240 秒技术安全上限约束，用户可随时停止。
- 保证非答题页可恢复、答题页绝不刷新。
- 保证题库零写入、旧答题/提取模式零行为回归。
- 由 Codex 在当前 macOS 实机完成无头和可视化真机验收。
- 版本升级到 `2.7`，提交并推送源码到 `origin/main`，生成 macOS ARM64 与 Windows x64 本地安装包。

## 5. 非目标与明确不做

- 不把无码答题实现成答题模式的功能精简版。
- 不修改现有答题模式和提取题库模式的业务逻辑。
- 不重写扫码授权、验证码、人脸或第三方认证协议。
- 不伪造 token、Cookie、二维码或学校验证状态。
- 不在无码模式中新增题库写入、校对、提取、冲突标记或待回写。
- 不把新站页面适配直接塞入现有 `runner.ts` 的 `answer/extract` 分支。
- 不开发未观察到的自由文本、连线、拖拽、排序、文件上传或 iframe 题型。
- 不新增独立工作台视觉体系或重新设计现有界面。
- 不执行 GitHub Release、Tag、OTA 或安装包上传。
- 不提交构建产物、浏览器 profile、账号数据、日志、密钥或临时文件。
- 不承诺 Windows 真机安装验证；Windows x64 只做本地构建和静态产品核验，除非后续另有真实 Windows 环境证据。

## 8. 功能需求

### REQ-001 第三工作模式与完整配置继承

触发条件：用户选择学生并切换工作模式。
前置条件：学生账号已存在；任务未运行或允许切换配置。
用户操作：点击现有工作模式分段控件右侧“无码答题”。
系统行为：

- 工作模式顺序固定为“答题 / 提取题库 / 无码答题”。
- 新模式使用独立持久化值 `noqr`；不得复用 `answer` 或 `extract`。
- 无码答题的登录、课程检测、作答、保存、交卷、取分和重答业务必须有独立模块边界；不得把新站页面分支塞进现有 `answer/extract` 的业务函数。
- 工作台模式按钮可以复用现有 UI 控件，但只能做模式选择和状态转发；旧 `answer/extract` 不得 import 无码模块，不得依赖新页面选择器或新流程状态。
- 模式按学生独立保存；运行中锁定；停止后恢复编辑。
- 选择无码模式后显示并启用“作业重新答题次数”。
- “应用当前配置到全部学生”同步工作模式、执行环境、课程范围和重新答题次数。
- 完整继承全部课程/可选课程、多学生、账号并发、课程并发、无头/可视化、课程/作业分页、课程日志、历史成绩、满分跳过、日期窗口、次数上限和重新答题次数。
- 现有账号缺少新工作模式值时默认解释为 `answer`。
- 切换提示必须显示“模式已设为：无码答题”。
数据变化：更新目标学生的 `work_mode`；不改动旧模式数据。
状态变化：`answer/extract/noqr` 三态切换；运行中锁定；停止后恢复。
正常结果：第三按钮可见、可持久化、可运行，旧学生配置不丢失。
异常处理：运行中切换被拒绝；持久化失败显式报错。
禁止行为：复用旧模式值、只改 UI 不改后端状态、切换影响其它学生、默认迁移成未知值。
对应 AC：AC-001。

### REQ-002 学生账号、登录与会话

触发条件：启动无码学生任务。
前置条件：学生账号存在；浏览器 profile 可创建或复用。
用户操作：通过现有工作台启动，不直接打开学校深链。
系统行为：

- 始终从 `/login/index.html` 进入。
- 有效持久化会话可自动重定向首页；否则填写现有账号和密码。
- 登录中按钮显示“加载中...”，请求未结束时持续等待。
- 登录成功：进入 `/index.html`、登录表单消失、`.menu-items` 或 `.course-card` 等首页业务标记出现。
- 登录失败：仍停留登录页且表单可见，并有明确错误/HTTP 4xx/5xx；或加载结束且无网络活动仍无法进入首页。
- URL 已进入首页但内容空白时，归类为“登录成功但首页加载失败”，刷新首页恢复，不直接重新登录。
数据变化：仅更新当前学生的会话与运行状态，不记录凭据。
状态变化：登录中 → 成功/失败/等待用户处理。
正常结果：进入首页并继续课程检测。
异常处理：慢登录继续等待；用户可停止；验证码/扫码/人脸出现时暂停并通知用户。
禁止行为：固定秒数超时刷新、重复提交、直接打开首页深链、绕过验证、记录账号密码、Cookie 或 token。
对应 AC：AC-002。

### REQ-003 课程检测与课程范围

触发条件：登录首页就绪。
前置条件：首页“形考作业”入口可用。
用户操作：无需逐门手工操作；沿用现有全部课程/可选课程设置。
系统行为：

- 点击“形考作业”，读取右上角课程菜单。
- 课程项使用 `.van-popover__action.top-pop-item`，当前课程使用 `.top-pop-active`。
- 课程菜单中的“中文”“English”“切换课程”是语言/操作默认项，不是课程；必须从课程快照、选课、检测和并发统计中排除，但点击真实课程时继续使用其原始 DOM 顺序。
- 课程数量、名称和顺序按真实菜单读取，不写死。
- 逐门切课，等待该课程 `.work-item` 或明确空态。
- 同一学生共享一个 persistent context；课程并发 `N` 表示最多 `N` 个独立页面/lane 同时推进，在单个页面上切课必须串行。
- 非答题页空白时按恢复预算刷新；连续刷新仍无 `.work-item`、明确空态或骨架时，只标记本轮当前课程暂无可见作业，不得升级为整门课程检测失败。
- 一门课程无作业、失败或不支持不得阻断其它课程和其它学生。
数据变化：形成当前学生的课程与作业展示数据。
状态变化：课程菜单读取 → 切课 → 作业列表/空态/失败。
正常结果：全部课程被检测，选择范围正确进入执行队列。
异常处理：切课失败、未知页面、第三方嵌入、课程身份不匹配明确失败并隔离。
禁止行为：直接打开课程深链、上一门课内容冒充当前课、按课程名猜身份、空作业阻断其它课程。
对应 AC：AC-003。

### REQ-004 作业筛选与满分/次数规则

触发条件：课程作业列表就绪。
前置条件：现有作业状态、日期和次数规则可用。
用户操作：沿用现有课程范围和重新答题次数。
系统行为：

- 沿用日期窗口、满分跳过、次数上限、网上记分作业/阶段性测验等现有规则。
- 作业卡使用 `.work-item`，开始作答使用 `.work-btns .btn-item:nth-child(1)`。
- 入口 URL 的 `workType` 白名单精确为 `onlineWork`、`stageExam`；点击作业卡后必须以实际 URL 为准。
- 作业卡上的“客观题”标签只用于列表筛候选，不得覆写 URL 的 `workType`；其他值停止当前作业并隔离。
- 若测试时全部或大部分账号已完成作业、满分或无可作答作业，不得因此跳过真实答题验收；账号仍可重答时按现有规则继续重答，生产规则会跳过时应启用仅测试环境生效的强制未满分/强制待做开关，继续进入真实答题、保存、交卷和取分链路。
- 强制开关不得改变生产默认规则、不得写题库，测试结束恢复。
- 全部或大部分账号满分是测试环境事实，不是真机验收失败；只有真实站点无法进入任何答题页时才按客观受限记录。
数据变化：测试覆盖不改变真实作业分数；真实测试会新增作答记录。
状态变化：待检测 → 可作答/满分跳过/次数用尽/无历史/不支持。
正常结果：按现有规则正确选择作业。
异常处理：未知 `workType` 或不可恢复列表错误停止当前作业并继续。
禁止行为：生产环境绕过满分规则、无测试隔离的强制开关、把测试覆盖写成正式功能。
对应 AC：AC-004。

### REQ-005 题型识别与不支持边界

触发条件：答题页题目就绪。
前置条件：当前页面命中已确认页面契约。

### REQ-007 作答、保存与完成判定

触发条件：当前题目/复合组有可靠答案。
前置条件：页面未在刷新，当前题目身份已记录。
用户操作：程序填写答案并点击“下一题”。
系统行为：

- 单选/判断使用 `role="radio"` 和 `aria-checked`。
- 多选使用 `role="checkbox"` 和完整选中集合。
- 词汇匹配使用只读 `input[name="picker"]` 与底部 Picker。
- 判断题和英语阅读判断题先按 DOM 位置点击，再按正文断言；请求 `answerSelected` 中正确=`1`、错误=`0`，其他题按 DOM 零基位置。
- 普通单题保存调用 `SubmitJsonAsync`。
- 复合组保存调用 `SubmitAllJsonAsync`。
- 保存结果分为三层：L1 捕获本次新请求；L2 XHR 结束、HTTP 2xx、`success:true`、`result.status:"success"`；L3 页面按预期推进或最后一题出现“已是最后一题”。
- L1+L2 表示服务端已接受保存；L1+L2+L3 才允许继续下一题。
- 请求必须匹配当前 `workId` 和题目/题目集合。
- 同一题同时只允许一个保存动作。
- 每个成功保存的题位从开始处理到允许继续下一题至少保持约 3 秒节奏；复合题按成功保存题位数计算，题库/AI/保存/页面推进本身已超过 3 秒时不额外等待。节奏等待必须可被用户停止中断，不能变成固定业务超时。
- 保存请求等待和页面推进分别受 240 秒技术安全上限约束；到达上限时保留已有作答页面并停止当前作业，不刷新、不重建会话。
数据变化：更新当前题目页面状态和运行结果；不写题库。
状态变化：填写中 → 保存中 → 成功可推进/最后一题/失败/结果不确定。
正常结果：每道题/组保存成功再推进。
异常处理：慢响应持续等待；请求未发出不盲点第二次；页面先变但无响应不判成功；响应成功但页面未推进继续观察或标记未推进。
禁止行为：固定超时刷新、重复提交、只凭 toast/遮罩/题号变化判成功、最后一题不跳转判失败。
对应 AC：AC-007。

## 9. 数据、状态与业务规则

### 9.1 工作模式数据

```ts
type WorkMode = 'answer' | 'extract' | 'noqr'
```

- 旧账号缺失或非法 `work_mode` 时回退 `answer`。
- `noqr` 与 `answer` 共享 `display_mode`、`course_scope`、`answer_round_limit` 等学生级配置。
- `account_parallel`、`course_parallel`、`log_enabled`、`browser_visible_default` 继续使用现有全局设置。

### 9.2 页面前置与状态

- 登录成功必须同时满足 URL、表单消失和首页业务标记出现。
- 答题页就绪以 `.question-info`、题型和真实题目内容出现为准。
- 空白骨架存在时继续等待；答题启动页只能返回重进；已作答答题页禁止刷新。
- 课程/作业就绪以 `.work-item` 和当前课程匹配为准。
- 课程并发按同一 persistent context 下最多 `N` 个独立页面/lane 计；单页切课不并发。

### 9.3 保存请求

单题：

```text
POST /dotNet_api/api/services/app/HomeWorkStudent/SubmitJsonAsync
```

```json
{
  "workId": "<workId>",
  "homeWorkUniqueFlag": "<homeWorkUniqueFlag>",
  "workType": "onlineWork",
  "answer": {
    "bigQuestionId": "<bigQuestionId>",
    "questionId": "<questionId>",
    "useTime": 0,
    "answerContent": "",
    "answerSelected": "0"
  }
}
```

复合组：

```text
POST /dotNet_api/api/services/app/HomeWorkStudent/SubmitAllJsonAsync
```

```json
{
  "workId": "<workId>",
  "homeWorkUniqueFlag": "<homeWorkUniqueFlag>",
  "workType": "onlineWork",
  "answers": [
    {
      "bigQuestionId": "<bigQuestionId>",
      "questionId": "<questionId>",
      "answerSelected": "0",
      "answerContent": "",
      "useTime": 0
    }
  ]
}
```

最终交卷：

```text
POST /dotNet_api/api/services/app/HomeWorkStudent/FinishJsonAsync
```

```json
{
  "workId": "<workId>",
  "workType": "onlineWork",
  "homeWorkUniqueFlag": "<homeWorkUniqueFlag>",
  "paperStructUniqueFlag": "<paperStructUniqueFlag>",
  "useTime": 0
}
```

上例只展示 `onlineWork` 请求形态；实际请求必须保留入口 URL 的 `workType`，合法值仅 `onlineWork`、`stageExam`。作业卡“客观题”标签不得覆写该值。

业务成功响应：

```json
{
  "result": {
    "status": "success",
    "data": null,
    "message": null
  },
  "success": true,
  "error": null,
  "unAuthorizedRequest": false,
  "__abp": true
}
```

### 9.4 保存完成规则

- L1：捕获本次点击产生的新请求，并匹配当前 `workId` 和题目。
- L2：XHR `readyState=4`、HTTP 2xx、`success:true`、`result.status="success"`。
- L3：普通题推进；整组进入下一个大题；最后一题显示“已是最后一题”。
- L1+L2 为已保存；L1+L2+L3 为可继续。
- `useTime=0`、加载 toast、答题卡当前态不是失败或成功的单独依据。
- 判断题/英语阅读判断题的页面点击索引与请求值分离：点击 DOM 位置零基；请求值正确=`1`、错误=`0`。其他题请求值按 DOM 零基位置。

### 9.5 分数记录

- 记录接口：`GET /dotNet_api/api/services/app/HomeWorkStudent/GetAnswerHistoryListJsonAsync`。
- 返回字段：`homeWorkUniqueFlag`、`paperStructUniqueFlag`、`finishedTime`、`score`、`useTime`、`isMarked`、`paperId`、`remark`。
- 可能包含未完成记录、空 `useTime`、`"--"` 和重复时间。
- 以解析后的完成时间选择最新有效记录，并与 `.record-item/.score-num` 交叉核对。
- 仅有记录页标题、没有 `.record-item` 且无“暂无/没有记录/无记录”等明确空态时，先防抖确认网络活动，再按刷新预算刷新；交卷后暂时空态等待新记录出现。

### 9.6 题库零写入

运行期间只允许 `GET /rest/v1/questions`；禁止 `POST`、`PATCH`、`DELETE` 到 `questions`。本机 `writeback` 与 `extract_writeback` 不新增无码模式条目。

### 9.7 测试强制开关

- 只在测试环境可用，生产默认不可见或关闭。
- 可强制把满分/无待做作业纳入测试，不改变学校真实分数。
- 测试账号大部分或全部已完成作业时，开关用于继续真实答题验证，不得把“没有自然待做作业”当成验收阻塞。
- 不影响其它学生配置，不写题库。
- 测试完成恢复正常满分/待做规则。

## 11. 异常、边界与安全规则

- 非答题页空白允许按恢复预算刷新；答题页绝不刷新。
- 答题启动页空白/骨架返回作业区重进；已产生进度后白屏不自动恢复。
- 保存、登录、交卷慢响应继续等待，不设置固定业务超时。
- 用户停止时禁止新动作；已发请求等待完成或标记结果不确定。
- 扫码/企业微信/验证码/人脸出现时暂停并通知用户，不绕过。
- 未知题型/未知控件只停当前作业并继续其它任务。
- 题库答案不可映射、AI 回答不完整、复合组不完整时禁止提交残缺答案。
- 题库写请求、本机回写队列新增、旧模式行为变化构成验收失败。
- 账号、密码、Cookie、token、真实 ID、完整题干/选项、音频地址不进入日志或交付文档。
- 删除操作默认禁止；任何清理不得涉及项目外文件。
- 不 force push，不覆盖用户改动，不提交构建产物或依赖目录。
